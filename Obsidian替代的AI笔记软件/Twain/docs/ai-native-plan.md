# 共笔 AI 原生计划：从“能用”到“好用、开放、会协作”

> 状态：执行中 · 2026-09-27
> 来源：库笔记《对于markdown笔记软件思路的思考》
> 已确认的决定：保留 Swift 原生（SwiftUI/AppKit + 液态玻璃），插件和 HTML 笔记内嵌 WebView；文件夹笔记采用 `文件夹/文件夹.md`；插件采用“声明式 + HTML 扩展”；可以真实调用模型做验证（尽量用 haiku）；可以直接用真实库测试；视频总结软件是懂听 GotIt。
> 上一轮教训：“三种工作区模式”和“任务化”两版 UI 都回退了，原因是**没有实用性，只是换了界面布局**（把右侧 agent 栏放大挪到中间）。所以本计划里的每个新界面，都必须回答同一个问题：**它让用户多做成了哪件以前做不成的事？**

## 0. 目标与判断标准

1. **基础先过关**：编辑、排版、粘贴、文件夹操作、性能都不能输给 Obsidian。没做好这些，AI 功能也没有意义。
2. **AI 改笔记要可控**：任何 AI 产出都拆成能逐块处理的单元（批注、卡片、分段提案、流水线的一步），不再一次性甩出一大段长文。
3. **高度开放**：界面上划定可自定义的区域（工作台模块、空间），数据接口通用而非针对某一种数据，任何 app 都能按同一套协议接入。
4. **性能与稳定**：主线程不做文件 I/O 和全量计算；编辑器每次按键只处理改动的行；每一步都有测试或截图验证。

## 1. 现状问题清单（有依据的）

| # | 现象（用户原话） | 根因（已查明） | 处理 |
|---|---|---|---|
| B1 | 逗号后间距很长；`（）` 两个半括号交叉重叠；括号在行首显示异常 | 正文字体是 New York，中文靠级联字体回退到宋体。回退时 CoreText 会自动压缩和补齐标点宽度：实测“，”宽 25pt（应为 17pt），“）”只有 3pt。直接给中文字符指定宋体时，所有标点都恢复为 17pt | 排版时把 CJK 字符段显式设成对应的中文字体，不再依赖级联回退 |
| B2 | 列表的“点”提前渲染；自动添加 `- ` 的行为有问题，中间按一下删除键就乱了 | 活动行显示原始 `- `、没有缩进，非活动行画圆点并缩进 26pt，光标进出时文字左右跳动；删除键只删一个字符，留下 `-` | 列表统一用悬挂缩进，活动行的 `- ` 放进左侧边距，文字位置不再变化；在列表标记后按删除键时，整个标记一次删掉 |
| B3 | 侧栏底部渲染出了两个“新建笔记” | `Sidebar.swift` 在回退时重复挂了 `.searchable` 和 `.safeAreaBar` | 删除重复的那份 |
| B4 | 在别的编辑器里改了文件，被识别成 Claude Code 改的 | `filesChanged` 只要终端里有 agent 进程在运行，就把所有外部修改算到它头上 | 核对该 agent 的会话记录里是否真的写过这个文件；没写过就算作“外部编辑器”，直接载入，不进审阅 |
| B5 | AI 对话里的文字只能按块选中，不能跨块 | 回复里每一段都是独立的 SwiftUI `Text` | 整条回复渲染进一个只读的 `NSTextView`（富文本），可以连续选中和复制 |
| B6 | 不能粘贴图片和视频 | 编辑器没有处理粘贴板里的文件和图片 | 粘贴或拖入时存进附件目录（沿用 Obsidian 的 `attachmentFolderPath` 设置），插入 `![[名字]]`；图片在行内渲染，视频显示封面，点击播放 |
| B7 | 点“让 Claude Code 总结”时出现沙滩球 | `launch()` 在主线程上同步执行 `git commit` 快照，并读取全库 432 个文件（iCloud 上可能还要先下载） | 快照和对比都放到后台队列，启动 agent 不再等它们 |
| B8 | 长笔记输入卡顿（隐患） | 每按一次键，`restyle()` 都要重设整篇的属性、让整篇重新排版，`center()` 还会对全文做一次 `ensureLayout` | 改为增量排版：缓存每行的样式签名，只重排签名变了的行 |
| B9 | 缺少文件夹操作 | 侧栏只能显示文件夹 | 新建、重命名、删除、移动文件夹，文件夹笔记，在文件夹里新建笔记，拖动笔记换文件夹 |

## 2. 分阶段计划

每一步单独提交，并跑 `swift test`、`scripts/e2e.sh` 和截图核对。

### 阶段 A：基础功能与性能（先做）

- A1 **排版引擎重构**（`Editor.swift` 拆分出 `MarkdownStyler`）
  - 按行增量排版：计算每行的块状态（普通、代码块、frontmatter、列表层级），只重设签名变了的行，再加上新旧两条活动行。
  - 中文字体显式分段（B1）。
  - 列表：悬挂缩进、多级嵌套（Tab 和 ⇧Tab 调整缩进），圆点用矢量绘制并对齐 x 高度（B2）；删除键一次删掉整个列表标记。
  - 新增块和行内语法：多行围栏代码块（等宽字体加底色）、`#### ~ ######` 标题、`~~删除线~~`、`==高亮==`、`> [!note]` callout、YAML frontmatter（折叠显示）、表格行等宽对齐。
  - 行内嵌入：`![[图片]]`、`![](路径)` 渲染为图片附件，视频显示封面，活动行显示源码。
- A2 **粘贴与拖入**图片和视频（B6），附件目录读取 `.obsidian/app.json` 的 `attachmentFolderPath`，默认为 `附件/`。
- A3 **后台化**：agent 启动时的快照和运行结束后的对比放到后台（B7）；`Vault.scan` 放到后台并去抖，侧栏的树按文件夹建缓存（去掉 O(n²) 的过滤）。
- A4 **改动归属**（B4）：结合会话记录中的写入记录和时间窗口判断；判断为外部编辑器的直接载入，并给一条轻提示。
- A5 **侧栏修复与文件夹操作**（B3、B9）：
  - 文件夹笔记 `文件夹/文件夹.md`：点击文件夹打开它；它在文件夹里不作为子项重复显示。
  - 右键菜单：新建笔记、新建子文件夹、创建文件夹笔记、重命名（同时改文件夹笔记的名字，并更新双链）、在 Finder 中显示、移到废纸篓。
  - 笔记拖到文件夹上即移动；命令面板和 `twain` 命令里也有同样的文件夹操作。
- A6 **对话可跨块选中**（B5）。
- A7 **HTML 笔记**：`.html` 文件出现在侧栏里，用 WebView 渲染；外网请求一律拦截；可以切换到源码编辑。

### 阶段 B：Agent 协作（最重要的部分）

每一项都对应原笔记里的一个痛点，并且都是新能力，而不是换一种布局。

- B1 **AI 审阅批注**
  - 点工具栏的“AI 审阅”，agent 读完整篇，通过新工具 `annotate` 在具体位置留下批注。
  - 批注类型：问题、建议（附替换文字）、事实核查、结构。
  - 批注显示在正文右侧边栏，与段落对齐；原文按引用片段锚定，笔记改动后仍能找到位置。
  - 每条批注可以：**采纳**（把建议替换进正文，可撤销）、**忽略**、**追问**（在这条批注下继续对话）。
  - 数据存在 `.twain/annotations/`；agent 和 CLI 都可以读写（`twain annotations`、`twain annotate`）。
  - 解决的痛点：“AI 一下子写一大长串，无从下手”。审阅改成一条一条的小决定。
- B2 **实时伴写**：写作时停顿超过约 4 秒、并且新写了一段后，用快速模型（haiku）在边栏给一条很短的提问或思路。
  - 限速，并且同一段落只提一次。
  - 可以一键收起或关闭。
  - 和现有的 Tab 续写（ghost text）并存：一个补全文字，一个启发思考。
- B3 **分级阅览（像 skill 一样）**
  - 第一级是每篇笔记的“名片”：标题、标签、标题树和一句话摘要。
  - **零 token 默认**：本地抽取标题、首段和标签作为摘要，不调用模型。
  - **增量 AI 摘要**：只给没有摘要或内容已变化（按哈希判断）的笔记生成，多篇合并成一次 haiku 调用，每日有预算上限（默认 100 篇），由用户手动开启或运行命令触发。这就是对“token 怎么解决”的回答。
  - 用户可以在笔记信息面板里查看和编辑摘要；笔记 frontmatter 里的 `summary:` 优先级最高。
  - 新命令和 MCP 工具：
    - `skim`：列出某个范围内笔记的名片
    - `read --level 1|2|3`：名片、提纲或全文
  - agent 上下文中的约定改为“先 skim，再按需 read”。
- B4 **可自定义的协作流水线** `.twain/pipelines/*.md`
  - 每个流水线由多个 `## 步骤` 组成，每一步写明 agent、模型、提示词，以及 `gate: review | ask | none`。
  - 带审阅门的步骤会停下来等用户：接受提案、选择方案、或者写一句意见，然后才进入下一步。
  - 上一步的结果以 `{{steps.<名字>}}` 的形式传给下一步。
  - 内置流水线：“研究 → 大纲（审）→ 分节写作（逐节审）”“收件箱整理”“周回顾”。
  - 这是对“规定好、又能自定义的 pipeline”和“不要一次写一大长串”的直接回答。
- B5 **工作台 · 问库（研究台）**
  - 以 agent 为主的界面。答案**不是一篇长文，而是一组带出处的卡片**：结论、证据、分歧、待解问题，每张卡片都标注来源笔记和行号，点击即可跳转。
  - 每张卡片可以：钉住、展开、追问、划掉、“收进草稿”。草稿就是一篇普通笔记，由人按卡片逐张组装。
  - 可以选择范围：全库、指定文件夹、指定标签。
  - agent 用 `skim` 和 `read` 分级检索，再通过 `cards` 工具逐张提交卡片，卡片边生成边出现。
  - 与上次被回退的方案的区别：交互单位从“消息”换成了“可以挑选、可以组装、可以追溯来源的卡片”，协作靠挑选和组装完成，而不是等一篇长文再去读。

### 阶段 C：开放与自定义

- C1 **插件与空间**：`.twain/plugins/<id>/manifest.json`
  - 一个插件可以贡献以下内容：
    - `spaces`：空间，也就是用户自己创建的“模式”，例如日记、自律、子弹笔记、LLM Wiki
    - `modules`：工作台模块
    - `commands`：命令
    - `pipelines`：流水线
    - `templates`：模板
    - `collections`：数据集合的字段说明
  - 空间由以下几部分组成：一个文件夹范围、新建条目的模板、一组仪表盘模块、专属的 agent 规则和流水线。
  - 空间出现在侧栏顶部；进入空间后，中间显示它的仪表盘（原生液态玻璃卡片），同时可以照常打开笔记编辑。
  - 声明式模块（原生渲染）：
    - `today`：今天的条目，没有就新建
    - `habits`：打卡，写入数据集合
    - `chart`：数据集合的折线图或柱状图
    - `query`：按文件夹、标签、属性列出笔记
    - `tasks`：待办
    - `ask`：问库入口
    - `pipelines`：流水线按钮
    - `note`：嵌入一篇笔记
    - `stats`：统计
  - HTML 模块：`widget.html` 跑在 WKWebView 沙盒里（拦截外网），通过注入的 `twain` JS 桥调用与 CLI 相同的命令。
  - 内置四个插件，同时也是写插件的示例：**日记**、**自律**（睡眠、运动、打卡、周回顾）、**子弹笔记**（任务、事件、笔记符号和迁移命令）、**LLM Wiki**（raw → wiki，含 ingest、query、lint 流水线，以及 index 和 log）。
  - 设置里有“插件”页，可以启用、停用、新建空间（从模板创建）。
- C2 **通用数据接口**：数据集合 `.twain/data/<集合>.jsonl`，每行一条记录，字段不做限定。导入途径：
  - CLI：`twain data add <集合> --json '{…}'`、`twain data import <集合> 文件.csv|json`
  - 本地 HTTP：`POST /v1/data/<集合>`
  - 文件投放：把 `.json` 或 `.csv` 放进 `.twain/inbox/<集合>/`，自动导入
  - 查询：`twain data query`
  - 任何数据（睡眠、运动、阅读、记账……）都走同一套接口，**不需要等开发者为某种数据单独开发**。
- C3 **本地 HTTP 网关**：`127.0.0.1:27182`
  - 使用 Bearer token，在设置里查看或重置。
  - `POST /v1/call/<命令>` 调用命令表里对 agent 开放的全部命令，与 CLI、MCP 同一份权限分级。
  - 另有便捷接口：`/v1/data/*`、`POST /v1/notes`（导入笔记：只新建不覆盖，带来源标记，记入事件流）。
  - URL scheme `twain://open?…`、`twain://new?…`。
- C4 **打通懂听 GotIt**：不在共笔里为 GotIt 做专门适配，而是写一个示例适配脚本 `integrations/gotit-sync`，读取懂听的 `summary.md`，调用 `POST /v1/notes` 导入到 `视频总结/`，按外部 id 去重。验证用真实数据跑一遍。其他 app 照这个例子接入即可。
- C5 **创作者文档** `docs/plugins.md`：manifest 字段、模块类型、JS 桥 API、HTTP/CLI 接口、完整示例。

## 3. 关键设计决定

| 决定 | 选择 | 理由 |
|---|---|---|
| 插件形态 | 声明式 manifest，外加 HTML/JS 沙盒扩展 | 常见需求原生渲染，又快又一致；复杂需求交给 HTML，不受限制；两者用同一套命令接口 |
| 数据存储 | `.twain/data/*.jsonl` | 纯文本、可追加、能用 git 管理，agent 也能直接读 |
| 摘要存储 | `.twain/summaries.json`（提交到 git），frontmatter `summary:` 优先 | 用户编辑过的摘要不能丢；不强行改写用户的笔记正文 |
| 批注存储 | `.twain/annotations/<笔记路径>.json`，用引用片段锚定 | 不污染笔记正文；笔记被编辑后仍能重新定位 |
| HTTP 权限 | token + 仅本机，与命令表共用权限分级 | 与 socket、MCP 同一套规则，不另开后门 |
| 导入笔记 | 直接新建（不覆盖，文件名唯一），进事件流并提示用户 | 导入是用户在对方 app 里主动发起的；新建可以撤回，风险低 |

## 4. 风险

- **R1 增量排版出错**：块状态（代码块、frontmatter）会跨行传播。对策：每行签名包含它所在的块状态；传播到哪些行，就重排哪些行；补单元测试。
- **R2 WKWebView 沙盒**：用 `WKContentRuleList` 拦截 http 和 https，再注入 CSP；JS 桥只转发命令表里对 agent 开放的命令。
- **R3 模型额度**：伴写、摘要都要限速，并设每日上限；默认关闭伴写，打开后才运行。
- **R4 iCloud 库**：文件可能被系统清出本地（evicted），读取会阻塞。对策：所有全库读取都在后台进行。
