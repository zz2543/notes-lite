# 共笔视觉与动效升级计划：从“简洁”到“精美、灵动”

> 状态：待执行（只有文档，代码未动）· 2026-09-28
> 起因：用户认为现在的界面偏简洁，甚至有些简陋。希望的不只是换颜色，而是**流畅的动画和精美的页面**。
> 前提：在 [`perf-plan.md`](perf-plan.md) 完成后开始。性能重构腾出的主线程余量是做动效的前提；它的阶段 5 把颜色和尺寸收进了 `Theme`，并留出了 `Appearance` 接口。
> 硬性要求：**这部分必须能用 git 完全回退**。

## 1. 目标：三个层次

| 层次 | 内容 | 现状 |
|---|---|---|
| **色彩与质感** | 身份色、材质层次、背景氛围、插图 | 几乎全是系统灰和系统色，只有 Claude 有自己的颜色 |
| **动效系统** | 统一的动画参数、转场、共享元素、交互反馈、流式内容的呈现 | 零散的几处 `.snappy` 动画，页面切换、面板开合、内容出现大多是硬切 |
| **页面精修** | 每个页面重新做内部的层次、排版、细节：笔记头部、内容块、会话、审阅、空间、问库、引导、空状态 | 功能齐全，但页面内部偏“列表加文字”，缺少层次和细节 |

参考的品质水准：Things 3 的动效节奏、Craft 的页面精致度、Arc 的色彩氛围、Apple 天气和健身 app 的数据呈现。

## 2. 设计原则

1. **结构不变，页面内部可以重做。** 三栏结构、功能入口、快捷键都不变。上一轮“工作区模式”只是把面板挪了位置、没有实际用处，被回退了（见 `ai-native-plan.md`）。这次不挪面板，而是把每个页面本身做精致。
2. **动效要表达关系。** 每个动画都说明一件事：东西从哪来、到哪去、谁和谁相关、操作成功了没有。例如点侧栏的笔记，标题从侧栏那一行“飞”到页面顶部；接受 AI 的改动，卡片收进正文对应的位置。
3. **颜色要传达信息。** 颜色对应身份（哪个文件夹、空间、agent）、类型（提示、警告、代码）或状态（进行中、完成、待审阅）。纯装饰只留给背景氛围。
4. **正文可读性优先。** 写作区保持高对比、稳定；打字时不出现分散注意力的动画。精致体现在排版和内容块上，不体现在闪烁上。
5. **动画可以打断、跟手。** 所有动画都用弹簧，随时能被新操作打断，拖动类操作跟随手指或鼠标，不出现“等动画播完才能点”。
6. **不牺牲流畅。** 效果交给显卡（Metal 着色器、Core Animation 图层、`MeshGradient`、`Canvas`），动画期间不触发模型层更新和文字重排；开启“精美”外观后，`perf-plan.md` 第 1 节的所有指标照样达标。
7. **尊重系统设置。** “减少动态效果”时只保留淡入淡出；“降低透明度”时去掉玻璃和渐变；“增强对比度”时加深边框和文字。

## 3. 阶段 V0：方向与动效原型（不改 app 代码）

审美由用户决定，先看到效果，再写代码。

- **风格板**：三套方向的静态画面，每套都有浅色、深色，覆盖同一组页面：编辑器、侧栏、Agent 回复中、审阅、空间页。
  - **A 纸与墨**：温暖的纸张底色、墨色层次、细腻的衬线排版，动效克制优雅。接近 Craft、iA Writer。
  - **B 流光**：玻璃后面有缓慢流动的彩色渐变，随当前文件夹或空间变色；动效活泼，有弹性。接近 Arc。
  - **C 分区色彩**：每个文件夹、空间、agent 有自己的颜色，并贯穿侧栏、标题栏、标题强调、图表。
  - C 可以作为底子，和 A 或 B 组合。
- **动效原型**：做一个可以点的 HTML 原型（放在 `design/vivid/`，浏览器直接打开），演示第 4 节里最关键的 6 个动效：切换笔记、开合侧栏、Agent 流式回复、接受改动、勾选任务、打开命令面板。可以调速、慢放。
- 验收：用户选定风格方向和动效节奏（克制、适中、活泼三档），确认调色板。

## 4. 动效系统

### 4.1 统一参数（`Sources/Twain/Visual/Motion.swift`）

- 四档弹簧：`quick`（按钮、悬停，约 0.15s）、`standard`（面板、卡片，约 0.3s）、`expressive`（页面转场、共享元素，约 0.45s）、`gentle`（背景和氛围，数秒）。
- 编排规则：进入由快到慢、离开比进入快；列表项错开出现（每项间隔 20–30ms，最多错开 8 项）；同一时刻最多一个“主角”动画。
- 所有页面只从这里取参数，不再各写各的时长和曲线。V0 选定的节奏档位，就是这里的取值。

### 4.2 动效清单

| 场景 | 动效 | 用到的技术 |
|---|---|---|
| 切换笔记 | 标题从侧栏那一行移到页面顶部；正文向上淡入；旧笔记向下淡出 | `matchedGeometryEffect`、转场 |
| 开合侧栏和 Agent 面板 | 面板带弹性滑入，里面的行错开出现；正文宽度平滑过渡，不重排文字（依赖性能计划 4.1） | 弹簧动画、错开 |
| 文件夹展开 | 箭头旋转，子项依次落下 | `DisclosureGroup` 自定义样式 |
| 命令面板 | 从工具栏的按钮位置“长”出来，玻璃形状连续变形；关闭时缩回按钮 | `glassEffectID` + `GlassEffectContainer` 的形变 |
| Agent 流式回复 | 文字按行淡入上浮；“思考中”显示流光；工具调用排成一条时间线，每步完成时打勾 | `TextRenderer`、Metal 着色器、`symbolEffect` |
| 审阅 AI 改动 | 接受：改动卡片收进正文对应的行，行高亮一闪；拒绝：卡片缩小淡出；全部处理完，横幅变形成“已完成”提示后消失 | `matchedGeometryEffect`、高亮渐隐 |
| 批注 | 卡片从右侧滑入，和原文之间画出一条连接线；选中批注时原文高亮呼吸一次 | `Canvas` 画线、弹簧 |
| 勾选任务 | 勾线逐笔画出，复选框弹一下，迸出少量粒子（最多 0.5 秒）；划掉的文字从左到右划线 | `Shape.trim`、Core Animation 粒子 |
| 专注模式 | 周围的界面溶解消失，页面舒展到中间，背景渐暗 | 转场、模糊 |
| 空间和问库 | 图表从基线生长；数字滚动变化；卡片翻转显示背面信息 | Swift Charts 动画、`contentTransition(.numericText())` |
| 提示条和横幅 | 从边缘弹入，互相推挤不重叠，消失时缩成圆点 | 弹簧、`glassEffectID` |
| 悬停和按下 | 卡片轻微抬起加阴影，按钮按下缩小 | `hoverEffect`、按下样式 |
| 启动和引导 | 图标组装动画；引导页每一步有插图动画 | `PhaseAnimator`、`KeyframeAnimator` |

## 5. 页面精修

每个页面列出要达到的样子。结构和功能入口不变。

- **笔记页**
  - 页面头部：面包屑（带文件夹颜色）、大标题、元信息行（字数、修改时间、标签胶囊）。可选封面图，取自 front matter 的 `cover` 或 `banner`。
  - 排版：重新校准标题字号的层级、段落间距、中英文混排的字距，正文宽度可调。
  - 内容块：
    - Callout 带颜色和图标；
    - 代码块带语法高亮、语言标签和复制按钮；
    - 表格有表头底色和斑马纹；
    - 图片圆角加轻阴影，点击放大有转场；
    - 引用有左侧色条；
    - 分割线改成装饰样式。
  - 空笔记显示占位插图和快捷提示。
- **侧栏**：文件夹、空间用彩色图标；选中行有带颜色的背景；拖动笔记时，目标文件夹展开并高亮；底部按钮组做成一体的玻璃条。
- **Agent 面板**：用户和 agent 的消息有明确的层次；agent 回复卡片边缘带 agent 色；工具调用显示成时间线；输入框做成浮起的玻璃卡片，模型选择器做成胶囊。
- **审阅视图**：改动做成左右或上下对比的卡片，增删用柔和的红绿底色，逐块显示 agent 给出的理由，接受和拒绝按钮醒目。
- **空间页**：仪表盘卡片有统一的圆角、层次和身份色渐变标题区；图表使用统一的调色板；数据为空时显示插图。
- **问库**：研究卡片按状态（候选、采纳、丢弃）着色，可以拖动排序；来源笔记显示成可点的小卡片。
- **命令面板**：结果分组、带图标，当前项有高亮，右侧预览所选笔记的开头。
- **设置和引导**：设置页分区卡片化，每项有说明插图；引导页做成带插图动画的几步。
- **空状态和欢迎页**：用 SF Symbols 的多色、分层渲染配渐变做插图，不用位图资源。

## 6. 色彩与质感

- **身份色**：8–10 种，每种有浅色、深色两个版本，外加语义色（提示、成功、警告、危险、AI）。文件夹和空间可以右键设颜色，默认按名字自动分配。Codex 从普通文字色改为一种独立的颜色。
- **材质层次**：定义三层表面：纸张（正文）、卡片（内容块、会话）、玻璃（浮在上面的工具栏、面板、菜单）。每层有固定的底色、阴影和圆角，不再各处随手写。
- **背景氛围**：侧栏和工具栏的玻璃后面铺一层 `MeshGradient`，颜色取当前文件夹或空间，缓慢流动。窗口不在前台或低电量时变成静态。正文区不透出渐变。
- **对比度检查**：写一个脚本检查所有文字与背景的对比度（正文 ≥ 4.5:1，辅助文字 ≥ 3:1），浅色、深色都要达标，不达标不能提交。

## 7. 实现上的约束

- 动画期间不修改 `AppModel` 等模型层数据，只改视图自己的状态，避免触发大范围重算。
- 持续的效果（背景渐变、流光）用 `TimelineView` 配合着色器或 `Canvas` 实现，不用定时器改状态。
- 复杂的装饰层用 `drawingGroup()` 或 Core Animation 图层合成，不堆几十个 SwiftUI 视图。
- 编辑器里的视觉效果（代码高亮、内容块装饰）接进现有的按行增量排版和 `TwainLayoutManager` 绘制，只处理改动的行和可见区域。
- 不新增第三方依赖；着色器写成 `.metal` 文件，由 SwiftPM 一起编译。

## 8. 分阶段计划

| 阶段 | 内容 | 验收 |
|---|---|---|
| V0 | 风格板和动效原型（第 3 节） | 用户选定方向和节奏 |
| V1 | 地基：身份色、材质层次、动效参数、`经典 / 精美` 开关、对比度脚本 | 切换开关即时生效；“经典”截图逐像素一致 |
| V2 | 笔记页：头部、排版、内容块、切换笔记的转场、勾选任务 | 按键 p95 ≤ 8ms；切换笔记 ≤ 30ms（含转场开始）；录屏核对 |
| V3 | Agent 面板和审阅：会话层次、流式呈现、思考流光、工具时间线、接受和拒绝的动效 | 流式输出和长会话滚动零掉帧 |
| V4 | 侧栏、命令面板、提示条、专注模式 | 开合动画零掉帧 |
| V5 | 空间和问库：仪表盘卡片、图表动画、研究卡片 | 数据更新时只做过渡，不整块重建 |
| V6 | 设置、引导、空状态、欢迎页、插图 | 截图核对 |
| V7 | 整体打磨：统一节奏、检查每个动画能否被打断、无障碍三项设置逐项核对、全面跑性能 | 全部指标达标，用户试用确认 |

每个阶段结束都给用户看截图和录屏，确认后才进入下一阶段；不满意就在当前阶段调整，或 `git revert` 这一阶段的提交。

## 9. 验证方式

- **截图**：每个提交用 `TWAIN_SNAPSHOT` 出浅色、深色截图，放进 `docs/screenshots/vivid/`，与 `vivid-baseline` 对比。
- **动效录屏**：关键动效用屏幕录制留档（需要用户授予录屏权限），同时导出逐帧图，检查中间帧有没有跳动或错位。
- **性能**：每个阶段结束在“精美”外观下跑 `scripts/perf.sh`，并用 Instruments 的 Animation Hitches 模板检查新增的动画，所有指标不低于性能重构完成时的数据。
- **无障碍**：逐项核对“减少动态效果”“降低透明度”“增强对比度”。
- **可回退核对**：切到“经典”，截图与 `vivid-baseline` 逐像素一致；在临时分支上试一次 `git revert -m 1`，确认能干净撤销。
