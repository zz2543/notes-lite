# 共笔视觉升级计划：从“简洁”到“美观、多彩”

> 状态：待执行（只有文档，代码未动）· 2026-09-28
> 起因：用户认为现在的界面偏简洁，甚至有些简陋，希望在一定程度上更美观、更多彩。
> 前提：在 [`perf-plan.md`](perf-plan.md) 完成后开始。它的阶段 5 把颜色和尺寸收进了 `Theme`，并留出了 `Appearance` 接口；它腾出的主线程余量，也是做动效的前提。
> 硬性要求：**这部分必须能用 git 完全回退**，退回后与视觉升级前逐像素一致。

## 0. 回退保证

视觉升级有两道回退保障：git 分支负责彻底撤销，设置里的开关负责随时对比。

| 项 | 做法 |
|---|---|
| 基准点 | tag `vivid-baseline`，指向性能重构完成时的提交（`perf-p5`，或合并后的提交） |
| 工作分支 | 从 `vivid-baseline` 拉出 `ui/vivid`，全部视觉改动只在这个分支上做 |
| 提交粒度 | 一项视觉改动一个提交，每个提交附浅色、深色截图；任何一项都可以用 `git revert <提交>` 单独撤掉 |
| 改动范围 | 只改视图层：`Theme.swift`、新增的 `Sources/Twain/Visual/` 目录，以及各视图文件里的外观修饰符。**不改模型、数据格式、agent 接口和编辑器逻辑**，所以撤销时不会和性能重构或功能开发冲突 |
| 数据文件 | 用户给文件夹、空间设的颜色存在 `.twain/appearance.json`，不写进笔记本身，保持与 Obsidian 兼容。回退后这个文件会被忽略，删掉也不影响任何笔记 |
| 运行时开关 | 设置 → 编辑器 → “外观”：`经典 / 多彩`。选“经典”时走性能重构阶段 5 的原取值，截图与 `vivid-baseline` 一致。用于试用期间随时对比 |
| 合并 | 用户试用确认后，才用 `git merge --no-ff ui/vivid` 合回。合并提交可以用 `git revert -m 1 <合并提交>` 整体撤销 |
| 不推送 | 只在本地操作 |

完全回退：

```bash
git switch feat/ai-native              # 尚未合并：视觉改动只存在于 ui/vivid，什么都不用做
git revert -m 1 <合并提交>              # 已合并：整体撤销
git diff vivid-baseline -- Sources/    # 核对：撤销后与基准点应无差异（后续功能提交除外）
```

## 1. 设计原则

上一轮“工作区模式”被回退，原因是**只换了布局，没有实际用处**（见 `ai-native-plan.md` 开头）。这次视觉升级同样要回答“它有什么用”，所以定下四条：

1. **不改布局。** 侧栏、正文、Agent 面板的位置和结构都不变，只改颜色、质感和动效。
2. **颜色要传达信息。** 每种颜色都对应一种身份（哪个文件夹、哪个空间、哪个 agent）、类型（提示、警告、代码）或状态（进行中、完成、待审阅）。纯装饰只留给背景氛围这一处。
3. **正文保持安静。** 写作区的底色和正文颜色保持高对比、不动；色彩和动效集中在侧栏、工具栏、Agent 面板、空间、问库，以及“完成任务”“AI 回复”这类时刻。
4. **不牺牲流畅。** 效果交给显卡（Metal 着色器、Core Animation 图层、`MeshGradient`），不堆 SwiftUI 视图；开启“多彩”后，`perf-plan.md` 第 1 节的所有指标必须照样达标。

## 2. 阶段 V0：先定方向（不改 app 代码）

审美是用户的决定，先出样稿，确认后再写代码。

- 做三套方向的静态样稿（HTML 或图片，放在 `design/vivid/`），每套都有浅色、深色，覆盖同一组画面：编辑器、侧栏展开、Agent 回复中、一个空间页。
  - **A 纸与墨**：温暖的纸张底色、墨色层次、低饱和的彩色标签。质感高级、安静，接近 Bear、iA Writer 的方向。
  - **B 流光**：侧栏和工具栏的玻璃后面有缓慢流动的彩色渐变，随当前文件夹或空间变色。鲜明、现代，接近 Arc 浏览器的方向。
  - **C 分区色彩**：每个文件夹、空间、agent 有自己的颜色，这种颜色贯穿侧栏圆点、标题栏色调、标题强调、图表。颜色最有信息量。
- C 可以作为底子，和 A 或 B 组合。
- 验收：用户选定方向（或组合），并确认调色板。之后的阶段按选定方向执行，下面以“C + B”为例描述。

## 3. 分阶段计划

### V1 色彩系统

- 定一套 8–10 种身份色，每种都有浅色、深色两个版本，外加语义色：提示、成功、警告、危险、AI。
- `Theme` 增加 `Appearance.vivid`，所有颜色都从它取值。
- 写一个对比度检查脚本：正文与背景 ≥ 4.5:1，辅助文字 ≥ 3:1，浅色、深色都要检查，不达标就不能提交。
- 验收：对比度脚本全部通过；切换 `经典 / 多彩` 即时生效。

### V2 身份色：文件夹、空间、agent

- 文件夹和空间可以设颜色（右键 →“颜色”），默认按名字自动分配一种，保证不设置也有颜色。
- 侧栏：文件夹图标、空间图标用身份色；当前笔记所属文件夹的颜色淡淡地染在标题栏和状态栏上。
- Agent：Claude 保持现有的橙色；Codex 现在是普通文字色，改为一种独立的颜色。会话记录、审阅横幅、批注卡片都用各自 agent 的颜色，一眼能看出是谁做的。
- 验收：截图核对；颜色设置写入 `.twain/appearance.json`，笔记文件无任何改动。

### V3 背景氛围

- 侧栏和工具栏的玻璃后面铺一层 `MeshGradient`，颜色取当前文件夹或空间的身份色，缓慢流动。
- 正文区保持实色纸张，不透出渐变。
- 窗口不在前台、开启“减少动态效果”或低电量模式时，渐变停止变化，变成静态。
- 开启“降低透明度”时，退回纯色背景。
- 验收：`stress` 场景零掉帧；空闲时 CPU 占用与“经典”外观相差不超过 1%。

### V4 正文内容的颜色

每一项都只在“多彩”外观下生效：

- **代码块语法高亮**：先支持常见语言（Swift、Python、JS/TS、Shell、JSON、Markdown），接进现有的按行增量排版，只处理改动的行，不新增第三方依赖。
- **Callout 按类型着色**：`> [!note]`、`[!tip]`、`[!warning]` 等各有颜色和图标。
- **标签**：`#标签` 显示成彩色胶囊，颜色由标签名决定，同一个标签在各处颜色一致。
- **高亮**：`==高亮==` 支持几种颜色。
- **标题强调色**：可选，标题前的符号或下划线使用所属文件夹的颜色。
- **链接**：`[[双链]]` 和网址用强调色区分，存在与不存在的笔记用不同样式。
- 验收：按键 p95 仍 ≤ 8ms（含代码块的长笔记）；截图核对浅色、深色。

### V5 Agent 面板

- 回复卡片的边缘带一条细的 agent 色渐变；工具调用步骤用彩色图标区分读、写、搜索、运行。
- 流式回复用 `TextRenderer` 做逐行淡入，替代现在的直接出现。
- “思考中”用一个轻量的 Metal 着色器做流光效果，替代纯转圈。
- 验收：流式输出时帧率稳定；长会话滚动零掉帧。

### V6 空间与问库

- 图表使用统一的调色板（与身份色一致），空间卡片的标题区用身份色渐变。
- 问库的卡片按状态（候选、采纳、丢弃）使用不同颜色。
- 空状态配插图：SF Symbols 的多色、分层渲染加渐变背景，不用图片资源。
- 验收：截图核对；数据更新时图表只做过渡动画，不整块重建。

### V7 动效

- 切换笔记时正文做一次很短的淡入淡出（≤ 150ms），不影响切换耗时指标。
- 勾选任务时，复选框弹一下，并迸出少量粒子（Core Animation 粒子发射器，最多 0.5 秒）。
- 侧栏图标和按钮使用 `symbolEffect`（弹跳、替换动画）。
- 命令面板、提示条、批注卡片统一用弹簧动画。
- 所有动效都遵守“减少动态效果”：开启后只保留淡入淡出。
- 验收：Animation Hitches 模板零掉帧；开启“减少动态效果”后逐项核对。

### V8 外观方案

- 设置里提供“经典”“多彩”两种外观，外加 2–3 套预设配色（例如晨曦、森林、夜海），带实时预览。
- 预设只是 `Appearance` 的不同取值，不增加新的代码路径。
- 验收：每套预设都通过对比度脚本；浅色、深色截图齐全。

## 4. 验证方式

- **截图**：每个提交用 `TWAIN_SNAPSHOT` 出浅色、深色截图，放进 `docs/screenshots/vivid/`，与 `vivid-baseline` 对比。
- **性能**：每个阶段结束在“多彩”外观下跑 `scripts/perf.sh`，所有指标不低于性能重构完成时的数据。
- **无障碍**：逐项核对“减少动态效果”“降低透明度”“增强对比度”三个系统设置下的表现。
- **可回退核对**：切到“经典”外观，截图与 `vivid-baseline` 逐像素一致；在临时分支上试一次 `git revert -m 1`，确认能干净撤销。
