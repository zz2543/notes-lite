## 本轮目标与证据边界

用户希望 AI Agent 更自然地融入软件，更贴合最初设想；交互流畅度与动效精致度次之。先理解已有文档和实现，再按 grill-with-docs（grilling + domain-modeling）分轮澄清。

已检查产品计划、命名说明、性能/视觉计划、历史原型、已有截图、主要交互代码、Git 历史及构建入口。源文档《对于markdown笔记软件思路的思考》未在当前文件夹找到；`ai-native-plan.md` 转述了它，不能把转述视为用户全部原意。本轮没有启动真实模型、操作用户笔记库或实测当前帧率。

## 原设想与实现之间的差距

### 1. 原设想重视共同创作，通用路径仍以会话为中心

`docs/naming.md:13` 将产品定义为人和 Agent 共同写同一份 Markdown。`docs/ai-native-plan.md:6` 记录“工作区模式”和“任务化”两轮回退：调整布局未增加实际价值。Git 中存在对应的功能提交和回退提交 `b02178a`。

当前 `AppModel+Agents.swift:82–101` 的通用启动流程会退出专注模式、打开右侧 Agent 面板。会话复用依据 Agent、来源和运行状态，不以当前笔记绑定。这说明“当前位置发起一次帮助”与“进入某个 Agent 会话”仍紧密耦合。

**初次检查的产品假设**：主要问题可能是用户不断切换工作对象、重新交代意图，而不是 AI 能力数量不足。第一轮回答补充了更上层的目标：不同任务需要不同且可自定义的协作模式；单一连续写作流程不能代替平台定位。

### 2. 有实时上下文接口，但不等于自动延续用户的工作意图

`AppModel+Agents.swift:187–208` 注入当前笔记路径、空间规则和工具说明；`Commands.swift:453–476` 提供选区、光标、标题路径、反链、待审阅等状态。模型可以按“先 skim，再 read”的约定找资料。

这是已实现的上下文能力。它尚不能证明每次发起任务都会自动选择正确资料，也不能证明跨页面、跨会话的目标能连续保留。

### 3. 各类结果有不同的后续操作

| 当前形式 | 已有价值 | 衔接问题或限制 |
|---|---|---|
| 批注 | 原文锚定、就地采纳、可撤销、可以回复 | 追问依赖原会话仍在内存中（`Annotations.swift:27–95`） |
| 伴写 | 停笔后给短问题/角度，可保留为批注 | “问 agent”只把提示文字放入输入框，未完整传递其引用与上下文（`Companion.swift:212–216`） |
| 通用提案 | 分块接受/拒绝，保留理由和反馈 | 审阅页替换正文页；部分反馈仍需在会话中点击发送（`NoteDetail.swift:8–20`；`Workflow.swift:151–220`） |
| 问库卡片 | 有来源，可筛选、追问、逐卡收进草稿 | 新建研究台，再逐张追加到 `研究台/…md`，形成另一套工作路径（`ResearchDesk.swift:67–153`） |
| 流水线 | 多步执行，支持 ask/review 关口 | 用户需处理会话关口和文件审阅，运行状态单独维护（`Pipelines.swift:104–207`） |

“拆成小块”已经落地。下一步要回答的是：哪些块属于同一件正在推进的事，用户如何连续讨论、采用、修改、返回，而不是继续增加入口。

### 4. 主动帮助已存在，但边界并未统一

伴写默认关闭，停顿 3.5 秒、文字增长阈值、50 秒间隔与每小时上限共同控制触发；只看光标前最多 1500 个 UTF-16 单位及标题路径（`Companion.swift:121–161`）。自动化依赖用户配置并启用（`Automations.swift:188–248`）。

“自然”可能指更主动，也可能指用户明确发起后不离开当前内容；二者需要分别决定，不能把主动性当作天然正确的答案。

### 5. 可控修改有两种不同语义

提案先保留原文，采纳后写入；普通 Agent 也允许直接修改文件，再由用户审阅或还原（`AppModel+Agents.swift:200–204`；`Workflow.swift:21–88`）。原地协作设计必须说明“尚未采用的建议”和“已经写入的修改”有什么区别。

## 第四轮回答：默认模式与页面自适应

| 问题 | 用户回答 | 对设计的影响 |
|---|---|---|
| Q14 转换后的更新 | 同意建议 | 格式间保留来源关系，默认按需更新；不在后台默认重写另一份文件。自动更新可以作为可配置行为 |
| Q15 切换模式 | 承接历史 | 同一条交互记录可以在切换模式后继续使用此前交流；历史不因模式切换而丢失 |
| Q16 默认模式 | 自由共写、自适应学习、资料整理 | 自适应学习替代此前建议的苏格拉底学习；不将逐题提问作为学习模式的唯一互动形式 |
| 补充要求 | 系统页面也要高度自适应，不能简简单单换皮 | 页面应在功能组织和互动方式上响应模式及其工作过程，不能仅变换颜色、提示词或将同一聊天面板搬动位置 |

已确认的默认模式：

1. **自由共写**：围绕资料讨论、修改笔记，按需生成 MD 或 HTML。
2. **自适应学习**：用户提出主题，先用一些问题判断认知范围，确定学习范围，再讲解知识点并辅以小测，检验理解和加深记忆。
3. **资料整理**：读取多份材料，提出整理方案，再执行用户选定的操作。

### 页面自适应的具体化草案（待核对）

下表是对“高度自适应”的设计解释，不是已经实现或全部获确认的界面规格；模式作者仍可另行定义。

| 模式/阶段 | 页面当前应让用户做什么 | 候选页面组织 |
|---|---|---|
| 自由共写 | 对照材料讨论、创作并处理修改 | 资料、正文、局部讨论/修改按当前工作展开；按需生成的 HTML 可以成为当前成果视图 |
| 学习：判断理解 | 作答，让 Agent 识别已掌握和不熟悉的部分 | 当前问题和作答区域为主，允许表达“不知道”；不提前挤满完整讲义 |
| 学习：确定范围 | 看清建议学习什么、为什么，可调整范围 | 展示拟学习内容及其关系，把诊断结果连接到学习范围 |
| 学习：讲解 | 理解当前知识点、追问和尝试操作 | 讲解、例子、示意图或可交互演示按需要出现 |
| 学习：小测 | 独立尝试，再查看反馈 | 作答区域成为主内容；提交后出现结果与解释 |
| 学习：调整 | 根据表现补前置知识、换例子或进入下一点 | 更新当前路径和内容，而不是只在聊天末尾追加一段反馈 |
| 资料整理 | 比较资料与整理方案，选择要执行的操作 | 材料清单、方案和受影响文件可对照；执行后呈现具体结果 |

第五轮已确认支持运行中临时生成新交互界面、跨聊天复用同主题学习记录，以及切换不打断此前 Agent 行为。上表的具体页面排布仍是设计草案；对流畅度的具体实现尚未定案。

## 对现有扩展能力的核对

- 当前 `Plugin.Space` 包含文件夹范围、条目模板、仪表盘模块和 Agent 规则（`Sources/TwainCore/Plugin.swift:7–17`）。这提供了扩展基础，但并不直接定义任意交互模式。
- 当前 Agent 的空间规则根据笔记所属文件夹选择，优先最长匹配路径（`Sources/Twain/Spaces.swift:126–135`）。如果同一份资料要自由切换模式，这一绑定关系需要重新审视。
- HTML 模块已有命令桥，可以调用对 Agent 开放的命令；正式 `run` 命令可启动自定义命令或流水线（`Sources/Twain/WebNote.swift:209–225`；`Sources/Twain/Commands.swift:334`）。当前页面桥只提供 `call/open/onDataChange`，没有持续订阅 Agent 事件的接口；HTML 调用不带连接，不能使用 CLI 的 `watch`（`Sources/Twain/Automations.swift:30`）。
- 当前主要工作区的空间、问库、审阅、笔记视图分支仍由宿主源码决定（`Sources/Twain/NoteDetail.swift:8–20`）；现有文档未定义让模式任意组合这些区域的扩展契约。
- 切换空间不会停止全局 Agent 任务；打开普通笔记会清除当前空间。现有机制没有模式级工作现场保存/恢复契约（`Sources/Twain/Spaces.swift:91`；`Sources/Twain/AppModel.swift:209`、`:456`），不能把全局任务仍存在等同于模式之间已有上下文衔接。
- 现有 `ask` 能等待用户答案并返回原调用，但会固定打开 Agent 面板并显示会话问题卡片，没有指定模式/模块或自定义呈现位置的参数（`Sources/Twain/Workflow.swift:228`、`:252`；`Sources/Twain/AgentInspector.swift:514`）。复用交互能力时，需要区分等待与回传逻辑和默认界面。
- 现有 HTML 笔记的源码/预览切换仅针对同一 `.html` 文件，未建立 MD 对应关系；普通 HTML 笔记也没有注入 widget 命令桥（`Sources/Twain/NoteDetail.swift:48`、`:229`；`Sources/Twain/WebNote.swift:50`、`:70`）。用户提出的按需格式转换和 Type 栏格式切换，不能视为该源码/预览开关已经覆盖的体验；没有据此认定必须实现实时双向同步。
- widget 已能通过 `propose` 提交整篇或片段修改，但这是命令提案语义，不是视图字段与 MD 的自动同步；调用也未携带自定义模块身份（`Sources/Twain/WebNote.swift:212`；`Sources/Twain/Workflow.swift:56`、`:72`）。

结论：已有插件系统是可利用的基础；新模式需要覆盖界面组合、交互流程、Agent 行为以及运行中的界面生成，明显超出现有仪表盘扩展范围。
