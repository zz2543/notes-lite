# 共笔自适应工作区 · 一次性界面原型

问题：三种结构不同的工作区，哪一种更适合承载用户定义的 AI 模式、阶段变化和连续的交互记录？

**这是评审用的原型，不是正式实现。** Agent 回复、自然语言生成模式、运行中加入演示及文件转换采用预设的本地模拟。它能检验界面与交互关系，不能证明真实 Agent 能生成任意代码、开放接口已经完成或真实任务能可靠执行。

## 打开

直接打开 [index.html](index.html)，所有资源都在这一个文件中。也可在 Twain 目录运行：

```sh
python3 design/prototype/adaptive-workspace/run.py
```

然后打开 [原型页面](http://127.0.0.1:8840/?variant=B)。端口可通过 `--port` 修改。没有外部依赖、数据库、账号或真实模型调用；资料和状态仅在内存，刷新即重置。

## 三个方向

| URL 参数 | 结构 | 主要探索 |
|---|---|---|
| `?variant=A` | 稿纸与页边协作：资料导航、正文、页边线索 | 文档作为工作中心，AI 操作围绕正文出现 |
| `?variant=B` | 按阶段展开的舞台：当前互动居中，材料与记录在下方 | 页面随诊断、规划、讲解、小测发生功能变化 |
| `?variant=C` | 可组合的自由工作台：主交互、资料、线索与历史是独立面板 | 面板可重新组合，交流记录作为独立区域保留 |

底部浮动条可切换 A/B/C。左右方向键也能切换；输入框或弹窗中不截获方向键。切换方向保留当前模式、学习进度、文件版本、交流历史与正在运行的模拟 Agent。

## 可以体验的过程

1. **自适应学习**：回答两个诊断问题，查看因回答不同而变化的学习范围和讲解；加入图像，拖动参数；完成小测后新开交流，参考同主题记录。
2. **资料整理**：选择资料、查看方案、选择操作、开始执行。中途切到共写，原来的模拟 Agent 仍会完成，结果归回发起的记录并标注原模式。
3. **自由共写与格式转换**：编辑示例 MD，按需生成 HTML。再改 MD，已有 HTML 保留旧版本；提出更新后才改写。Type 入口可隐藏，HTML 的主要文本也可模拟转回 MD。
4. **创建模式**：描述需求，生成可操作草稿，在预览中回答并查看反馈，再采用为新的模式。示例解析支持对照辩论、逐句精读、每周回顾；不具备任意自然语言到代码生成能力。
5. **修改模式**：采用自定义模式后，可重新打开其定义、调整需求、再次预览并更新。可选模组在这个原型中由声明式区块模拟。
6. **自由工作台**：拖动面板到不同区域，或点面板标题上的移动按钮；当前交互状态保留。

“体验引导”提供三条推荐路径。“观察状态”展示模式、记录、文件版本与来源、运行归属、学习表现、整理选择、模式草稿和面板组合。未发送的交流输入保留在所属记录内。

## 动效依据

参考 `emil-animate`、`emil-design-eng` 和 `emil-apple-design`：

- 高频输入、图像拖动和键盘方向切换保持即时，不加入装饰动效。
- 阶段变化用于说明状态，用 WAAPI 的 opacity/transform，180ms，`cubic-bezier(0.23, 1, 0.32, 1)`。
- 原生 dialog 负责焦点、模态隔离和 Escape；进入 220ms，退出 160ms，opacity/scale。重新打开可打断退出。
- 面板放置后的布局变化使用 transform，220ms，`cubic-bezier(0.77, 0, 0.175, 1)`；拖放采用浏览器原生行为，不模拟惯性。
- 按下反馈 120ms；提示使用可重定向的 CSS transition；减少动态效果时保留淡入淡出、移除位移动效。
- 悬停样式按指针能力启用，支持减少透明度及增强对比度。

后台进度更新只更新状态提示，避免不断重建编辑区域。动效节奏仍需用户在实际交互中判断，截图不能证明动画品质。

## 验证与边界

已通过 JavaScript 语法检查，并在浏览器实际操作诊断与分支讲解、演示、小测、跨聊天参考记录、模式创建预览与采用、跨模式整理完成、格式生成及按需更新、隐藏 Type 入口，以及 A/B/C 切换。修复了方向切换的浏览器 history 名称冲突、未发送输入丢失和完成结果模式归属问题。

遵循 prototype 技能，未添加测试套件。尚未对真实模型、任意主题学习、任意第三方模式、正式持久化或生产性能作验证。浏览器关闭后不保留状态，也不运行真实文件操作。

## 捕获与结论

捕获分支：`codex/prototype-adaptive-workspace`。原型源代码、截图和本次产品定义作为评审依据保存，当前工作分支不切换；原型不合入正式应用。

**界面选择结论尚未产生。** A/B/C 是用于比较的设计假设；用户可选择某一方向，或组合不同方向的部件。后续选择及其理由应补充记录，再将验证过的设计重新实现到正式软件中。
