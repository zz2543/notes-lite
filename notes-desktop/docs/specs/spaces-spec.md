# 留白「空间」：由外部 Agent 编写的主题空间主页

日期：2026-10-18。状态：设计已与用户逐条确认；首版已实现（`feat/ai-native`），实测见 `../../../NotesLite/evidence/spaces/verification.md`。适用产品：留白（NotesLite，`feat/ai-native` 分支），不涉及原产品共笔。
相关决定：[ADR 0002](../adr/0002-space-pages-written-by-external-agents.md)、[ADR 0003](../adr/0003-space-pages-full-access-within-scope.md)；术语见 [GLOSSARY](../GLOSSARY.md)。

## Problem Statement

用户在留白里用 Markdown 记录健身、雅思学习这类长期主题，但笔记只能一篇一篇地看，看不出每天的进展，也没有顺手的地方快速记一笔。每个人的场景都不一样：有人记卧推重量，有人记背单词时长，固定模板满足不了。用户希望围绕一个主题有一个页面，用好看的图表展示进展、提供快捷录入，并且这个页面可以交给 Agent 按自己的场景生成和定制。同时，留白的根本原则不能变：笔记库就是普通文件夹，Markdown 文件是唯一真相，留白本身不内置 Agent。

## Solution

新增**空间**。空间是高于文件夹的独立实体，有名称和 emoji 图标，通过**范围**关联一个、多个文件夹或整个笔记库。每个空间对应笔记库内 `.留白/空间/` 下的一个 HTML 文件，即**空间主页**。

侧栏顶部新增「资料库 | 空间」切换。空间模式下：左栏是空间列表；中栏是范围内的文件树，顶部固定一项「主页」；右栏默认显示空间主页，点击文件时显示笔记编辑器。

空间主页的数据全部来自范围内笔记里的**记录表**（Markdown 表格，表头就是字段，一行就是一条记录）。空间主页自身不保存数据。留白给页面提供三层能力：跟随深色模式的样式包、5 个通用且可配置的小组件，以及 `lb` 接口。`lb` 是页面访问笔记的唯一通道，在范围内拥有完整读写权限。

新建空间时，留白生成空的空间文件，并打开助手栏，把一段提示词作为新对话交给内置助手（所用的命令行 Agent 读留白自动生成的**编写说明**后填写空间文件）；本机没有命令行 Agent 时改为把提示词复制到剪贴板，交给外部 Agent（2026-10-21 用户反馈，取代原先只复制到剪贴板的做法）。文件一有变化，留白自动刷新。安全网有三层：每次写入都进入可跨重启逐条撤销的**操作记录**；删除一律进废纸篓；写入后在界面顶部提示。

## User Stories

### 空间与导航

1. 作为笔记用户，我希望在侧栏顶部切换「资料库」和「空间」，以便在整理笔记和查看主题进展之间切换。
2. 作为笔记用户，我希望资料库模式和现在完全一样，以便新功能不打乱已有习惯。
3. 作为笔记用户，我希望在空间模式的左栏看到所有空间的 emoji 和名称，以便一眼找到要看的主题。
4. 作为笔记用户，我希望拖动调整空间顺序，并且顺序跟着笔记库保存，以便常用的空间排在前面，换台机器也一样。
5. 作为笔记用户，我希望点击一个空间后，中栏只显示它范围内的文件夹和文件，以便只看和这个主题相关的笔记。
6. 作为笔记用户，我希望中栏顶部固定有一项「主页」，以便从任何笔记一键回到空间主页。
7. 作为笔记用户，我希望在中栏点击笔记后，右栏打开正常的笔记编辑器，以便在空间里直接编辑笔记。
8. 作为笔记用户，我希望范围是整个笔记库时，中栏的树和资料库一致，以便用一个空间做全局工作台。
9. 作为笔记用户，我希望同一个文件夹可以属于多个空间，以便日记既能用来统计学习时长，也能用来统计训练。
10. 作为笔记用户，我希望删除空间只删除空间文件、不动任何笔记，以便放心清理不用的空间。
11. 作为笔记用户，我希望通过空间的右键菜单「显示源文件」看到它的 HTML，以便需要时检查或手动修改。
12. 作为笔记用户，我希望能修改空间的名称、图标和范围，以便主题变化时调整。

### 新建与生成

13. 作为笔记用户，我希望点「新建空间」后填写名称、选择 emoji、选择范围（一个、多个文件夹或整个库），以便快速建立一个主题入口。
14. 作为笔记用户，我希望新建后留白自动打开助手栏，让内置助手按提示词生成主页（没有可用的 Agent 时复制到剪贴板），以便不用离开应用。
15. 作为笔记用户，我希望提示词里包含编写说明路径、空间文件路径、空间名称、范围，以及范围内现有记录表的位置和表头，以便 Agent 不用到处翻找就能生成合适的主页。
16. 作为笔记用户，我希望空间还没有主页时，右栏显示「让助手生成主页」按钮（旁边可“复制提示词”交给外部 Agent），空间的右键菜单也有「让助手生成主页」，以便随时重新生成。
17. 作为笔记用户，我希望 Agent 写完空间文件后，右栏自动显示新主页，以便不用手动刷新或重启。
18. 作为外部 Agent，我希望在 `.留白/空间/编写说明.md` 读到完整、最新的文件格式、样式、组件和接口说明，以便一次写对空间主页。
19. 作为外部 Agent，我希望编写说明随留白升级自动更新，以便不会按过时的接口写页面。
20. 作为将来的 Agent 侧栏，我希望复用同一份编写说明和 `lb` 接口，以便不用另起一套生成通道。

### 记录表

21. 作为笔记用户，我希望记录就是笔记里一张普通的 Markdown 表格，以便不打开留白也能读、改、用其他工具处理。
22. 作为笔记用户，我希望用「笔记路径#标题」指定一张记录表，不写标题时用笔记中的第一张表，以便一篇笔记里可以放多张记录表。
23. 作为笔记用户，我希望路径可以使用 `{月}`、`{今天}` 这样的占位符，以便记录按月或按天自动分篇。
24. 作为笔记用户，我希望目标笔记或表不存在时留白按表头自动新建，以便第一次录入不用先手动建表。
25. 作为笔记用户，我希望字段类型按列内容自动推断（数字、日期、文字），以便图表和统计不用另外声明类型。
26. 作为笔记用户，我希望在编辑器里手动修改记录表后，打开着的空间主页自动刷新，以便两边看到的数据一致。

### 组件与样式

27. 作为笔记用户，我希望空间主页的颜色、字体、圆角和卡片和留白原生界面一致，并跟随深色模式，以便它看起来是留白的一部分。
28. 作为笔记用户，我希望用 `lb-stat` 看到一个大数字（计数、求和、平均、最新值，按周期统计），以便直接知道本周练了几次。
29. 作为笔记用户，我希望用 `lb-chart` 看到折线图或柱状图，以便看出重量或时长的趋势。
30. 作为笔记用户，我希望用 `lb-calendar` 看到打卡热力日历，以便看出坚持情况。
31. 作为笔记用户，我希望用 `lb-quick-add` 按记录表的表头和字段类型自动生成输入框，日期默认填今天，以便几秒钟记一条。
32. 作为笔记用户，我希望用 `lb-records` 看到最近 N 条记录，以便确认刚才记录的内容。
33. 作为外部 Agent，我希望组件不绑定任何主题、只认记录表和字段，并且可以配置 `label`、单位、颜色和标题，以便同一套组件适用于任何场景。
34. 作为外部 Agent，我希望自由写 HTML/JS，并和组件混用，以便组件不够用时自己实现。
35. 作为笔记用户，我希望组件在数据变化后自动重绘，以便不用手动刷新。

### lb 接口与权限

36. 作为外部 Agent，我希望用 `lb.query` 查询带类型的记录，并支持过滤、排序和数量限制，以便自己计算统计值。
37. 作为外部 Agent，我希望用 `lb.notes`、`lb.read`、`lb.scope` 列出和读取范围内的笔记，以便基于笔记内容做展示。
38. 作为外部 Agent，我希望用 `lb.append`、`lb.update`、`lb.remove` 增删改记录，以便实现录入和修正。
39. 作为外部 Agent，我希望用 `lb.create`、`lb.write`、`lb.rename`、`lb.move`、`lb.trash` 管理范围内的笔记，以便实现更复杂的整理功能。
40. 作为外部 Agent，我希望脚本可以自己写入、不需要用户点击，以便实现自动同步之类的功能。
41. 作为外部 Agent，我希望用 `lb.on("change")` 订阅范围内文件变化，以便自己写的部分也能实时刷新。
42. 作为笔记用户，我希望范围外的路径（包括 `..`、符号链接逃逸、隐藏目录、库外文件）一律被拒绝，并且页面不能运行命令，以便一个页面出错不会波及其他笔记。
43. 作为笔记用户，我希望空间主页只能重写自己的空间文件，不能改范围，也不能碰其他空间文件和编写说明，以便页面不能给自己扩大权限。

### 安全网

44. 作为笔记用户，我希望空间主页的每次写入都进入操作记录，并按每条记录逐条撤销，以便只撤回出错的那一条。
45. 作为笔记用户，我希望关闭并重新打开留白后仍能撤销，操作记录保留 30 天，以便过几天发现问题也能挽回。
46. 作为笔记用户，我希望空间主页删除的笔记一律进入废纸篓，以便误删可以找回。
47. 作为笔记用户，我希望页面写入后右栏顶部显示「主页刚修改了 N 条记录 · 查看」，点「查看」打开操作记录，以便知道页面在后台做了什么。
48. 作为笔记用户，我希望操作记录能显示操作类型、路径、时间、来源空间和修改前后的差异，以便判断要不要撤销。

### 联网、存储与错误

49. 作为外部 Agent，我希望空间主页可以联网、引用 CDN 上的库、拉取外部数据，以便使用成熟的图表库和第三方数据。
50. 作为笔记用户，我希望联网拿到的数据必须写进记录表，以便数据仍然留在我的 Markdown 里。
51. 作为笔记用户，我希望页面的 localStorage 只保存界面偏好，并且每个空间互相隔离，以便上次选的标签或周期能记住，又不会变成第二个数据源。
52. 作为笔记用户，我希望页面报错或加载失败时，右栏顶部显示错误条，以便知道主页坏了。
53. 作为笔记用户，我希望错误条上有「复制错误给 agent」按钮，以便把错误交给 Agent 修复。

### 一致性

54. 作为笔记用户，我希望改名或移动文件夹、笔记时，所有空间文件里的范围和组件 `source`/`target` 路径同步更新，以便空间不会因为整理笔记而失效。
55. 作为笔记用户，我希望 `.留白/` 不出现在资料库的笔记列表和搜索结果里，以便它不干扰日常笔记。
56. 作为笔记用户，我希望外部 Agent 改了空间文件后直接刷新、不需要审阅，以便迭代主页时足够顺手。

## Implementation Decisions

### 已确认的产品决定

- 空间页面由外部 Agent 直接写文件生成；留白首版不内置 Agent，不新增 MCP、socket、HTTP 等外部控制入口（ADR 0002）。
- 空间是高于文件夹的独立实体，通过范围关联文件夹或整个库；不做「文件夹主页」，也没有「主文件夹」。
- 每个空间是 `.留白/空间/<名称>.html`。范围、图标用 `<meta>` 声明（范围用 `lb-scope`）。正文为空表示「还没有主页」。
- 空间顺序存在笔记库内 `.留白/空间/` 下的一个小配置文件里，跟着库走。
- 记录只认 Markdown 表格，frontmatter 以后再考虑。定位方式是「笔记路径 + 可选标题」，路径支持占位符；目标不存在时按表头自动新建。
- 字段类型自动推断：整列都是数字的当数字，`YYYY-MM-DD` 形式的当日期，其余当文字。
- `lb` 在范围内拥有完整读写权限，脚本可以自己写入（ADR 0003）。
- **空间文件访问**：页面通过 `lb` 只能重写**自己**的空间文件；不能访问其他空间文件、编写说明和顺序配置。
- **撤销**：粒度是**每条记录**（一次调用修改多条记录，就拆成多条可以分别撤销的条目；笔记级操作如改名、删除各算一条）；保留 **30 天**，到期自动清理；跨重启保留。
- 允许联网；外部数据必须写入记录表；localStorage 只存界面偏好，每个空间隔离持久化。
- 外部 Agent 修改空间文件后不审阅，直接刷新。

### 组件 2.0（2026-10-21 用户逐条确认，取代上文第 27–35 条中的具体组件与 `lb` 别名）

- **方向**：原生精致风（像 macOS 的「健康」「天气」小组件）：大圆角卡片、柔和层次、强调色只做点缀，深浅色都耐看。空间页面外壳与主页组件一起重做。
- **不再兼容旧写法**：删除 `lb-*` 组件名、`--lb-*` 变量与页面里的 `lb` 接口名，只留 `space-*` 与 `space`。打开仍用旧写法的主页时，错误条提示「这个主页用的是旧组件」并带「让助手重新生成」按钮。
- **外壳**：标题区显示空间图标、名称和一行范围说明（如「范围：健身/」），右侧「让助手修改」「复制提示词」「查看源码」。滚动条用应用自己的样式。
- **视觉要求**：图表横轴按真实时间；量级差异大的两组数据各用一根纵轴；柱子只圆顶部、底部贴住基线；打卡日历按数据跨度显示（12–53 周），深浅按数据分布分档；记录中的数字照原样显示不四舍五入，放不下时少显示列；快捷录入有标题、按钮用强调色、日期选择是自己做的中文版；卡片无描边（浅色：底色 + 很轻的阴影；深色：底色 + 一圈细亮边）；间距按 4 / 8 的倍数；灰字对比度不低于 4.5:1。
- **图表库**：引入 ECharts（用户：好看的就行），只在页面用到图表时加载；颜色、字体、动效接设计变量。图表支持悬停提示、多系列、面积、环形。
- **组件**：大数字、图表、打卡日历（含连续打卡天数）、最近记录、快捷录入，以及新增的：布局（网格、分区标题）、目标进度（进度条或圆环）、筛选器（本周 / 本月 / 全部等，管同一分区内的组件，无分区时管整页，记住上次选择）、可编辑表格（排序、筛选、行内修改）、清单（勾选写回记录表）、计时器（关掉或重启后继续；结束时追加日期、开始时间、时长（分钟））、笔记卡片（标题、摘要、修改时间，点击在编辑器打开）。
- **勾选字段**：整列都是 `[x]` / `[ ]` 时推断为「勾选」类型（第四种字段类型）。
- **组件里改数据**：最近记录与表格可行内修改、删除；删除不确认，底部提示「已删除 1 条 · 撤销」；每次改动都进操作记录。
- **新接口**：`space.open(path)` 在编辑器打开范围内的笔记；范围外拒绝。
- **示例空间**：「新建空间」旁菜单「新建示例空间」，以及没有空间时空状态里的链接。建立名为「组件示例」的空间（重名则「组件示例 2」…），范围是新建的同名文件夹，内含健身记录、待办清单、读书进度、专注时长四篇示例笔记；主页由应用写好，用上全部组件，每张卡片下附可复制的写法。示例空间与普通空间一样可改可删。
- **编写说明**同步新组件与示例，内置助手生成主页时会用到它们。
- **顺序**：先外壳、样式基础与示例空间，截图给用户确认方向；确认后铺开全部组件与交互；最后更新编写说明、删除旧写法（任务 31–34）。

### 设计地基（2026-10-22 用户确认）

这一轮只打地基、接通助手，不重做内置组件。目标：基础设施足够强，助手能写出好看且自定义的页面；助手可以只用组件、只用自己的写法，或者混用。

- **样式地基**（`spaceKit/foundation.css`，随样式包注入）：10 个色相（`--space-<色相>` 及 `-deep` / `-tint` / `-glow`），`data-hue` 给一张卡片和里面的元素定色相；字号、圆角、间距、阴影变量；`.space-bento` 4 列网格（`.space-m` / `-l` / `-full` / `-tall`，窄窗口变 2 列、1 列）、`.space-header`、`.space-section`；卡片风格 `.space-glow`（光晕）、`.space-glass`（毛玻璃）、`.space-tint`（柔彩）；文字与小部件（大数字、分段切换、标签、玻璃按钮、进度条、进度环）；动效（`data-space-count` 滚动数字、`.space-lift` / `-spotlight` / `-float` / `-shimmer` / `-live` / `-breathe`），幅度跟随动效强度（`--space-motion-amplitude`：轻 0.6、标准 1、强 2），减弱动态效果时全部停止。
- **新接口**（`spaceKit/runtime.js`，拼进 `space`）：`space.chart(元素, option)` 用内置 ECharts 6 画图，配色字体跟随设计变量、尺寸变化重绘、外观变化换色；`space.load("echarts")` 拿原始库（应用自带，从 `notes-space:` 协议的 `/kit/echarts.js` 离线提供，用到时才加载）；`space.theme()` 返回解析好的 `rgb()` 颜色、字体和动效设置，`space.on("theme")` 在变化时通知；`space.open(path)` 在应用里打开范围内的笔记（范围外 `outside-scope`，不存在 `not-found`）；`space.toast(文字, { action, onAction, duration })`。
- **编写说明第 4 版**：新增「设计与自定义」：先声明页面完全由助手决定，再给推荐做法、检查清单和全部变量、类名、接口，以及光晕数字卡和自己写组件的例子。
- **示例空间**：在内置组件前加「自定义写法」一节，不用组件，只用地基、`space.chart` 和 `space.open` 画出来。
- **下一轮**：按地基重做 5 个内置组件、加新组件，以及旧页面的提示。

### 模块

- **空间库（NotesCore，深模块）**：发现和解析 `.留白/空间/*.html` 的 meta（范围、图标），新建、改名、删除空间，读写顺序配置，生成新建提示词（含范围内记录表的位置和表头），生成和覆盖编写说明。
- **记录表（NotesCore）**：在现有表格解析基础上，提供按「路径#标题」定位、展开占位符、带类型推断的读取、按记录追加/修改/删除，以及按表头新建，并且尽量保留原文其余内容。
- **lb 请求处理（NotesCore，本功能的主要接缝）**：输入一条来自某个空间的结构化请求（方法名 + 参数，JSON 形式），输出 JSON 结果或结构化错误。职责：解析范围并校验路径（复用 `Workspace` 的库内路径校验，额外拒绝范围外路径、符号链接逃逸，以及除本空间文件外的所有 `.留白/` 路径）；执行记录和笔记操作；删除走废纸篓；每次写入都追加到操作记录。页面端的 `lb` JS 对象和全部组件只通过这一个入口访问原生能力。
- **操作记录（NotesCore）**：持久化的追加式记录，内容包括操作类型、路径、修改前后内容（或差异）、时间和来源空间；提供按条撤销和 30 天清理。存储位置在实现时确定，必须跨重启保留。撤销时如果目标已被其他人修改，要给出可理解的冲突反馈，不能静默覆盖。
- **文件监听（NotesCore）**：新增持续的文件系统监听（如 FSEvents），把范围内文件和空间文件的变化分发给打开着的空间主页，也可供以后增量更新 `Workspace.refresh()` 使用。用户在编辑器里保存、外部 Agent 写文件、`lb` 写入，三种来源都要触发。
- **引用同步**：沿用改名、移动时更新链接的思路，同步更新所有空间文件中 `lb-scope` 和组件 `source`/`target` 里的路径。
- **空间主页视图（NotesLite）**：独立的 WKWebView 配置，和公式渲染用的沙盒分开。不拦截网络；为每个空间使用各自隔离的持久化数据存储；注入样式包、组件脚本和 `lb` 桥接脚本；捕获 JS 错误和加载失败，显示错误条和「复制错误给 agent」；显示写入提示条。桥接层只负责转发，不包含业务逻辑。
- **界面（NotesLite）**：侧栏顶部的「资料库 | 空间」切换；空间列表（可拖动排序、右键菜单）；新建/编辑空间表单；范围内的文件树（顶部固定「主页」）；右栏在空间主页和编辑器之间切换；操作记录面板。
- **样式包与组件（随应用分发的 Web 资源）**：CSS 变量和 class（如 `--lb-accent`、`.lb-card`），跟随深色模式；`lb-stat`、`lb-chart`、`lb-calendar`、`lb-quick-add`、`lb-records` 5 个 Web Components，都通过 `lb` 读写，订阅 change 后自动重绘。

### lb 接口契约（能力范围已确认，方法名以编写说明为准）

- 读：`query(source, {filter, sort, limit})` 返回带类型的记录；`notes(folder)`；`read(path)`；`scope()`。
- 写记录：`append(target, record)`、`update(...)`、`remove(...)`。
- 写笔记：`create(path, content)`、`write(path, content)`、`rename(...)`、`move(...)`、`trash(path)`。
- 事件：`on("change", handler)`。
- 所有方法都是异步的；错误以结构化形式返回（如范围外、目标不存在、表头不匹配），供页面和错误条显示。
- **范围不能被页面改变**：页面重写自己的空间文件时，`lb-scope` 必须保持不变；尝试修改会被拒绝。这是落实「只能改自己」与 ADR 0003「范围就是权限」的工程约束，不是新的产品决定。

### 待实现时确定的工程细节（不是用户已确认的决定）

- 占位符的完整集合和语法。建议至少包括 `{今天}`、`{年}`、`{月}`、`{周}`，日期统一用 `YYYY-MM-DD`，具体以编写说明为准。
- 范围为整个笔记库时 `lb-scope` 的写法，建议用 `*`。
- 图标 meta 的字段名、顺序配置文件的文件名和格式、操作记录的存储位置。
- 记录的身份标识（`update`/`remove` 怎样定位一行），以及没有 `id` 列时的匹配规则。

## Testing Decisions

- **好测试的标准**：只测外部行为，也就是对临时笔记库发请求后，看到的 JSON 结果、磁盘上的 Markdown、操作记录和撤销效果。不依赖内部类型、私有方法或视图层级。
- **主接缝：lb 请求处理**（已与用户确认）。绝大多数行为都在这里测：记录表定位与占位符展开、类型推断、按表头自动新建、增删改记录且保留笔记其余内容、笔记的新建/改名/移动/删除（进废纸篓）、范围拒绝（`..`、符号链接、隐藏目录、其他空间文件、编写说明、修改自身 `lb-scope`）、操作记录逐条撤销、跨重启后撤销（重新打开库）、30 天清理（注入时钟）。先例是现有的 `WorkspaceTests`：用临时目录建库，打开、操作，再断言磁盘内容。
- **空间库与引用同步**：仍以笔记库为边界，测试新建空间生成的文件和提示词内容、顺序配置持久化、删除空间不动笔记、文件夹改名后空间文件中的路径被更新。先例是现有的引用更新测试。
- **一个真实窗口的端到端测试**（已与用户确认）：真实的 `NoteWindow` 和 WKWebView 加载一个临时库中的空间主页，验证组件渲染出数据、`lb-quick-add` 录入后磁盘出现新行、外部改动记录表后页面自动刷新、页面抛错时出现错误条，以及切到空间模式、点击文件进入编辑器、点「主页」返回。先例是现有的 `EditorWorkflowTests`（真实窗口、临时库、不 mock）。
- 样式包的深色模式、图表美观度、联网加载 CDN 库在原生应用里人工检查，并在 `NotesLite/evidence/` 中留下截图和说明；不能用构建成功代替。
- 当前没有经过确认的性能数值；文件监听和刷新延迟要记录实测条件和结果，不设未经确认的硬性门槛。

## Out of Scope

- 在留白内置 Agent 面板或 Agent 侧栏（以后另做，届时复用编写说明和 `lb`）。
- 为外部 Agent 提供 MCP、socket、HTTP 或命令注册表等控制入口；外部 Agent 只通过写文件生成空间。
- 「文件夹主页」、点击文件夹打开主页、「主文件夹」概念与 `lb-home` meta。
- 在资料库导航里增加与「全部笔记」「最近打开」并列的「主页」项。
- 只允许追加、或必须用户点击才能写入的权限模型。
- 空间主页自己存数据（`data.json`、localStorage 存记录）。
- frontmatter 记录、每天一篇笔记的数据形式、自由格式的行式日志。
- 和主题绑定的专用组件。
- 访问库外文件、运行命令。
- 单独的全局工作台（由范围为整个库的空间覆盖）。
- 外部 Agent 修改空间文件时的审阅流程。
- 交接文档第 9 节的编辑器按键性能问题（单独排期；`Workspace.refresh()` 的后台化和增量更新可以和文件监听一起做，但不作为本功能的验收项）。

## Further Notes

- 本规格修订了 [留白规格](spec.md) 的 Out of Scope 中「生成式工作区」「自定义模式平台」「可编辑 HTML 产品线」三项：空间主页属于范围内。「Agent 面板……」和「外部控制入口」两项保留。ADR 0002 修订 ADR 0001。
- 现有的「恢复上次删除」只覆盖本次打开期间，不满足操作记录要求，需要另做持久化机制，不能直接沿用。
- 现有 `Workspace.refresh()` 遍历时跳过隐藏文件，`.留白/` 因此天然不出现在笔记列表里；空间库需要单独读取该目录。
- 现有公式渲染沙盒拦截网络、使用非持久化存储，空间主页必须使用另一套配置，不能改动公式沙盒的行为。
- 交接来源：用户提供的《留白-空间功能设计交接》（2026-10-18），第 7 节中的待定项已在本次确认：空间文件只能改自己、顺序存在库里、撤销按每条记录且保留 30 天、外部修改不审阅；Agent 侧栏的形态不在本次设计范围内。
