# 助手栏规格：通过外部命令行 Agent 与笔记互动

日期：2026-10-19。状态：设计已与用户逐条确认，助手形象与助手栏布局已在原型中校准，取值见[设计规范](../design-system.md)。架构决定见 [ADR 0005](../adr/0005-agent-sidebar-via-external-cli.md)。上位规格：[跨平台桌面版重写规格](desktop-rewrite-spec.md)、[界面与动效规格](ui-motion-spec.md)。实施排在里程碑 5（新版取代旧版之后），布局与助手形象现在定稿。

## Problem Statement

用户在笔记软件里写作、整理时，想直接让 Agent 帮忙：问一问当前笔记或整个笔记库、让它找资料、改笔记、写空间主页。现在只能切到终端运行 Claude Code 等工具，再回来看结果；改了哪些笔记、能不能退回，都不直观。旧产品共笔曾有 Agent 面板和一个粒子球图标，新版重写时排除了全部 Agent 能力，现在用户希望以更好的形式加回来。

用户同时不希望被反复打断：不想每改一处就点一次同意，也不想 Agent 的能力被限制。

## Solution

在主窗口右侧加入可折叠的**助手栏**（第四栏）。**助手**通过用户本机的外部命令行 Agent 运行：Claude Code、Codex、DeepSeek Harness、Pi。助手以选中的笔记或文件夹为工作目录，以完全权限运行。

每**一轮**结束后，助手栏出现一张审查汇总卡片，列出这一轮改过的笔记，默认一键全部保留，也可以撤回其中某一篇。每一轮的改动都作为一条操作记录，可以整体撤销；撤销依靠每轮开始前对整个笔记库做的增量快照。

助手由**助手形象**代表：空闲时是一个有眼睛和嘴的圆润实体，工作时散成粒子，状态之间连续变形。这延续了共笔粒子球的语言，又形成独立、有辨识度的角色。

## User Stories

### 打开与布局

1. 作为写作者，我希望在主窗口右侧打开助手栏，一边看笔记一边和助手对话，以便不用切到终端。
2. 作为写作者，我希望助手栏收起时用卡片右上角的助手形象按钮、打开时用助手栏的关闭按钮，或随时用 ⌘J / Ctrl+J 开关助手栏，以便随时收起它，把空间还给正文。
3. 作为写作者，我希望助手栏打开时正文卡片相应变窄，而不是被遮住，以便同时看清笔记和对话。
4. 作为写作者，我希望窗口较窄时，左侧导航自动从双栏收成单栏、再收成图标栏，为助手栏腾出位置，而助手栏始终停靠在右侧、不浮在正文上；专注模式下也一样，正文卡片铺满其余空间。
5. 作为用户，我希望助手栏折叠时，按钮上的小助手形象仍然显示助手当前的状态，以便知道它是否还在工作。

### 选择 Agent

6. 作为用户，我希望软件自动检测本机装了哪些命令行 Agent（Claude Code、Codex、DeepSeek Harness、Pi），以便不用手动配置。
7. 作为用户，我希望在助手栏顶部切换使用哪一种 Agent，以便按任务选择。
8. 作为用户，我希望一种 Agent 都没装时，助手栏显示安装指引而不是报错，以便知道下一步怎么做。
9. 作为用户，我希望每个对话固定使用开始时选的那一种 Agent，以便对话前后一致。
9a. 作为用户，我希望在 Agent 名称旁选择本次新对话用的模型（默认跟随 Agent 自己的设置），以便按任务换模型而不用去改 Agent 的配置。

### 工作目录与上下文

10. 作为用户，我希望选中一篇笔记时，助手以它所在的文件夹为工作目录，并自动把这篇笔记作为上下文，以便直接问“这篇写得怎么样”。
11. 作为用户，我希望选中一个文件夹时，助手以这个文件夹为工作目录，以便让它处理整个主题下的笔记。
12. 作为用户，我希望对话的工作目录在开始时固定，中途切换笔记不会改变它，但当前打开的笔记会随每一轮更新到上下文里，以便对话不会因为我浏览别的笔记而乱掉。
13. 作为用户，我希望助手栏一直显示当前对话的工作目录，点击可以跳到对应的文件夹。
14. 作为用户，我希望在输入框里用 @ 提及其他笔记加入上下文，也能去掉自动附上的当前笔记。
15. 作为用户，我希望要换工作目录时新开一个对话即可。

### 对话

16. 作为用户，我希望在助手栏里看到消息流，助手的回复逐步出现，以便不用等它全部完成。
17. 作为用户，我希望助手读了哪篇、改了哪篇、运行了什么命令，折叠成一条时间线，需要时展开查看，以便了解它做了什么又不被细节淹没。
18. 作为用户，我希望查看和继续以前的对话，以便接着上次的工作。
19. 作为用户，我希望对话记录保存在应用自己的数据目录里，不写进笔记库，以便我的 Markdown 不被污染。
20. 作为用户，我希望让助手按编写说明编写或修改空间主页，以便用同一个入口定制空间。

### 权限、审查与撤销

21. 作为用户，我希望助手拥有完整权限，可以读写文件、运行命令、联网，中途不弹出授权询问，以便它能真正完成任务。
22. 作为用户，我希望每一轮结束后只审查一次：一张汇总卡片列出这一轮改过的所有笔记，默认一键全部保留，以便最多点一次。
23. 作为用户，我希望在汇总卡片里展开查看每篇笔记的改动，并单独撤回其中某一篇，以便只保留满意的部分。
24. 作为信任助手的用户，我希望在设置里改为“直接保留”，不再出现审查卡片，以便完全不被打断。
25. 作为用户，我希望每一轮的全部改动在操作记录里是一条，撤销它就整体还原这一轮，以便随时反悔。
26. 作为用户，我希望助手改了工作目录以外的笔记，甚至改写或删除了图片附件，也都能审查和撤销。
27. 作为用户，我希望设置里写明：笔记库以外的文件不在快照范围内，无法撤销。
28. 作为用户，我希望快照保留 30 天后自动清理，设置里能看到快照占用的磁盘空间，并能立即清理。
29. 作为拥有一万篇笔记、1 GB 附件的用户，我希望快照不明显拖慢每一轮的开始，也不占用大量内存。

### 助手形象

30. 作为用户，我希望助手形象空闲时是一个正圆、有细线条五官的实体，会眨眼，视线跟着鼠标，以便感到它是一个“在场”的伙伴。
31. 作为用户，我希望助手开始工作时，实体散成一团粒子，按思考、搜索、读取、写入、运行命令等状态以不同方式流动，以便一眼看出它在做什么。
32. 作为用户，我希望助手完成后粒子重新聚拢成实体，并露出短暂的满意表情，以便知道这一轮结束了。
33. 作为用户，我希望助手等我回应时，实体看向我、嘴张成小圆，外圈有呼吸光环，以便知道轮到我了。
34. 作为用户，我希望出错时实体变红、表情担忧，以便立刻注意到。
35. 作为用户，我希望所有状态之间都是连续变形，不切换图标，以便动效连贯自然。
36. 作为用户，我希望界面上同一时间只有一个助手形象，它在 22 与 48 像素下都清晰醒目，以便它在按钮、头像和助手栏顶部都好看。
37. 作为开启了系统“减弱动态效果”的用户，我希望助手形象只显示各状态的静态画面。

## Implementation Decisions

### 已确认的决定

- **运行方式**：调用本机外部命令行 Agent，支持 Claude Code、Codex、DeepSeek Harness（`dsh`）、Pi，四者地位相同。启动时检测已安装的 Agent；对话开始时选定，之后不变。
- **权限**：不限制。以 Agent 的完全权限模式启动（不逐项授权、全自动），可读写任意文件、运行命令、联网；中途不出现 Agent 自带的授权询问。空间主页的范围限制（ADR 0003）不适用于助手。
- **工作目录**：选中笔记时为其所在文件夹，并自动附上该笔记作为上下文；选中文件夹时为该文件夹。对话开始时固定，换工作目录需新开对话。当前打开的笔记每一轮更新到上下文。
- **写入审查**：外部 Agent 直接改写磁盘，因此审查发生在改动之后，含义是“保留或撤回”。设置提供两种模式：**每轮结束后统一审查**（默认）与**直接保留**。审查卡片默认操作是“全部保留”，可展开后逐篇撤回。不提供逐处或逐篇即时确认。
- **快照与撤销**：每一轮开始前对**整个笔记库**做增量快照；一轮结束后对比出改动的文件，作为一条操作记录，撤销即整体还原，审查时的逐篇撤回也基于同一快照。
  - Markdown 与文本文件：存入应用数据目录中按内容去重的存储；每轮只检查修改时间与大小，只为变化的文件存新版本。
  - 附件：macOS 使用 APFS 写时复制克隆；Windows 在首次打开助手栏时于后台复制一份基线，之后只存变化的文件。笔记库超过约 10 GB 时，Windows 改为只记录附件元数据并在设置中提示。
  - 内存只保存文件清单。笔记库以外的文件不纳入快照。
  - 快照保留 30 天后自动清理，对应操作记录随之不可撤销；设置显示占用空间并提供“立即清理”。
- **对话存储**：存在应用数据目录，不写入笔记库。
- **空间主页**：助手编写空间主页时遵循编写说明（ADR 0002 要求复用）。新建空间、空间右键菜单或空主页上的“让助手生成主页”会打开助手栏，以笔记库根目录为工作目录、用 Agent 切换当前所示的 Agent 与模型新开一个对话，把空间的提示词作为第一条消息发出（2026-10-21 用户反馈）；上一轮还在进行时只提示，不打断；本机没有 Agent 时改为复制提示词。
- **布局**：可折叠的第四栏，位于正文卡片右侧、铺在窗口材质上，正文卡片相应变窄；开关为助手栏收起时卡片右上角的助手形象按钮、打开时助手栏顶部的关闭按钮，以及 ⌘J / Ctrl+J；助手栏始终停靠，不使用浮动面板（用户明确要求）。开关助手栏时栏宽以无回弹的快速过渡变化（约 0.26 秒），收起助手栏不会让左侧导航重新排布，只有打开助手栏、调整窗口或更改导航设置时才重新确定导航档位。空间不够时让左侧导航逐级收窄：助手栏打开时，窗口宽度不小于 1180 像素保持双栏导航；960–1180 像素自动临时切到单栏导航；小于 960 像素收成图标栏，点击图标或“展开导航”恢复单栏。窗口窄于 1180 像素时助手栏宽度从 340 像素减为 300 像素。专注模式下助手栏仍停靠在右侧，正文卡片铺满左侧其余空间。用户在设置中选了单栏导航时始终用单栏。阈值为原型取值。
- **模型选择**（2026-10-21 用户反馈，方案 A）：Agent 切换下方有一个“模型：…”按钮，只在新对话开始前可选；菜单第一项是“默认（…）”，不传模型、交给 Agent 自己的设置，括号里写出设置里选的模型（读得到时）；其后是从该 Agent 本机配置读到的模型，最后是“手动输入…”。读取来源：Claude Code 为 `~/.claude/settings.json`（或 `CLAUDE_CONFIG_DIR`）的 `model`、`env` 中的 `ANTHROPIC_MODEL` 与 `ANTHROPIC_DEFAULT_{OPUS,SONNET,HAIKU}_MODEL`、`availableModels`，外加别名 opus / sonnet / haiku；Codex 为 `~/.codex/config.toml`（或 `CODEX_HOME`）顶层与 `[profiles.*]` 的 `model`；Pi 为 `~/.pi/agent/settings.json` 的 `defaultModel` 与 `enabledModels`（不含通配）以及 `models.json` 里声明的模型。选中的模型以命令行参数传入（Claude Code 与 Pi `--model`，Codex `-m`），记在对话上，对话的每一轮都用它；对话进行中模型显示在 Agent 名称旁，不能更改。每种 Agent 记住上次的选择，用于下一次新对话（存在应用设置里）。DeepSeek Harness 没有逐次指定模型的参数，只能在它自己的设置（`~/.dsh/settings.yaml` 的 `agent-default-model`）里改，因此只显示“模型：默认（…）”，不提供选择。手动输入只接受能作为一个命令行参数的名称。
- **助手栏内容**：顶部是大号助手形象、当前 Agent 切换、对话历史入口与工作目录；中间是消息流，工具调用折叠为时间线；每轮末尾是审查汇总卡片；底部是输入框，带自动附上的当前笔记与 @ 提及。

### 助手形象

- **形态**：贴近 Grok Bot 的扁平、单色、几何风格（用户要求）。实体是正圆，平涂主题墨色（浅色模式近黑、深色模式近白），无渐变、无光晕；表情主要靠一对**圆角方块眼睛**，下方一条短而细的嘴；周围有几颗细小粒子缓慢环绕。
- **与 Grok Bot 保持区别**：风格接近但不照搬。保留三处自有特征：有一张会变化的细嘴；工作时整个形象散成粒子球、完成时粒子融合回实体（延续共笔粒子球）；实体周围的环绕粒子。不使用 Grok Bot 的具体造型、配色方案或名称。
- **状态与表情**：

| 状态 | 形态 | 表情与附加 |
| --- | --- | --- |
| 待命 | 实体 | 圆角方块眼，偶尔眨眼，视线跟随鼠标；嘴为浅浅的微笑 |
| 思考 | 粒子球 | 一道缓慢的流光转过球面 |
| 搜索 | 粒子球 | 光带横向扫过 |
| 读取 | 粒子球 | 光带上下扫动 |
| 写入 | 粒子球 | 亮弧绕球旋转 |
| 运行命令 | 粒子球 | 横纹闪动 |
| 完成 | 实体 | 眼睛折成 ^ ^，嘴角上扬，轻轻一弹；随后回到待命 |
| 等你回应 | 实体 | 眼睛放大、看向正前方，嘴张成小圆角方块，外圈呼吸光环 |
| 出错 | 实体 | 变红，眼睛内侧上挑成担忧状，嘴角下撇，轻微一抖后静止 |

- **变形**：实体与粒子球之间由同一组粒子连续融合：聚拢时实体从中心长大，粒子沿轻微弧线向内汇聚、按各自延迟先后到达，被长大的实体触到即融化，形成中的实体边缘带柔光，五官在融合接近完成时才淡入；散开时反向。融合用无回弹的平滑弹簧，不出现突然出现或消失的画面。状态切换不交换图标。
- **尺寸与出现位置**：同一时间界面上只出现一个助手形象，避免堆叠。助手栏打开时只在助手栏顶部显示（48 像素，完整表情），消息不带头像；助手栏收起时，卡片右上角显示 22 像素的开关形象（只有眼睛，没有嘴），并继续显示状态。
- **减弱动态效果**：只显示各状态的静态画面。
- **参数**：粒子数量、变形时长、表情细节在原型中校准后写入[设计规范](../design-system.md)。

## Testing Decisions

- **好测试的标准**：只测外部行为，即对临时笔记库运行一轮后，磁盘上的文件、操作记录与撤销结果，以及助手栏中用户可见的状态；不依赖内部实现。
- **接缝 A（核心库）**：快照与还原是主要测试对象。对临时笔记库建立快照、模拟一轮改动（改写笔记、新建与删除笔记、改写与删除图片、改动工作目录以外的笔记），再验证：改动清单正确；整轮撤销与逐篇撤回都完全还原；未改动的文件不重复存储；30 天清理（注入时钟）；`.notes/` 搬迁不受影响。
- **接缝 B（运行中的应用）**：用一个**假的命令行 Agent**（按脚本输出消息并修改文件的小程序）代替真实 Agent，测试 Agent 检测、对话开始与继续、工作目录的确定、时间线展示、审查卡片的全部保留与逐篇撤回、“直接保留”模式、助手栏开关、专注模式下的停靠、左侧导航按窗口宽度切换档位，以及收起助手栏时左侧导航不重排。不在自动化测试中调用真实的模型服务。
- **人工验收**：在 macOS 与 Windows 上分别用至少一种真实 Agent 完成一轮问答与一轮改写；检查助手形象各状态与变形的观感；按用户的真实规模（约一万篇笔记、1 GB 附件）测量每轮开始前的快照耗时、内存与磁盘占用。

## Out of Scope

- 应用内直接调用模型接口的运行方式（以后可作为另一种运行方式加入）。
- 限制助手权限，或逐处、逐篇的即时写入确认。
- 笔记库以外文件的快照与撤销。
- 对话记录跨设备同步。
- 语音输入、多 Agent 协作、自动化与流水线。
- 在里程碑 5 之前实现助手栏的功能（布局预留与形象设计除外）。

## Further Notes

- 快照耗时与磁盘占用的数字目前是估算，需要在实现时按用户的真实笔记库测量。
- 各 Agent 的完全权限启动方式、输出格式与对话恢复方式各不相同，需要在实现时逐一核实，并为每种 Agent 写一个适配层；接缝 B 的假 Agent 应模拟这一适配层的输入输出。
- 产品新名称确定后，助手形象的轮廓可按名称对应的物品微调。
