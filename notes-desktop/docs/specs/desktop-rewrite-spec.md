# 跨平台桌面版重写：Electron 单一代码库取代 macOS 原生旧版

日期：2026-10-19。状态：设计已与用户逐条确认（追问记录见本日会话），尚未实施。开发代号 `notes-desktop`，产品新名称待定。架构决定见 [ADR 0004](../adr/0004-cross-platform-desktop-rewrite.md)；它取代 [ADR 0001](../adr/0001-independent-native-notes-app.md) 中“macOS 原生、跨平台首版不属于范围”的部分。

## Problem Statement

用户的笔记软件（旧版名“留白”）目前只能在 macOS 上运行：界面用 SwiftUI，编辑器用 AppKit，视觉效果用 Metal，换到 Windows 电脑就无法使用自己的笔记库。为每个平台分别维护一套原生代码，功能必然分叉，一个人也维护不过来。

用户希望把它当作一个全新版本来做：一套代码在 macOS 和 Windows 上提供完全相同的功能，以后再考虑 Linux 和移动端；现有的笔记库不用迁移，打开就能用；编辑体验不能比旧版差，动效和字体排版还要比旧版更讲究；打开软件不能等很久。

## Solution

在仓库根目录新建自包含目录 `notes-desktop/`，用 Electron + TypeScript + React 完全重写，Motion 负责动效，CodeMirror 6 负责编辑器。以现有三份规格为验收基线：

- [独立笔记软件规格](spec.md)：资料库、笔记、编辑、专注模式、链接与附件、外部修改冲突等；
- [空间规格](spaces-spec.md)：空间、范围、空间主页、记录表、编写说明、操作记录；
- [退出列表与空行插入光标规格](list-exit-caret-spec.md)：列表延续、退出列表、分隔空行、插入光标、文字选区。

基线中与本规格冲突的部分以本规格为准（见 Implementation Decisions 末尾“对基线的修订”）。新版达到功能对齐并通过验收后取代旧版；旧版 `NotesLite/` 从现在起只修严重 bug，之后归档保留。

新版分四个里程碑交付：骨架 → 编辑对齐 → 空间 → 完成对齐。

## User Stories

### 跨平台与产品身份

1. 作为同时使用 Mac 和 Windows 电脑的用户，我希望两台电脑上用同一个笔记软件、同样的功能，以便不用在两套操作方式之间切换。
2. 作为用户，我希望 Windows 版和 Mac 版的笔记、空间和设置项完全一致，以便不会出现“这个功能只有 Mac 上有”。
3. 作为 Mac 用户，我希望快捷键用 ⌘，Windows 上对应用 Ctrl，以便符合各自平台的习惯。
4. 作为 Mac 用户，我希望窗口保留红绿灯按钮，菜单在系统菜单栏里，以便它像一个正常的 Mac 应用。
5. 作为 Windows 用户，我希望窗口右上角是系统的最小化、最大化、关闭按钮，菜单收在窗口内的菜单按钮里，以便它像一个正常的 Windows 应用。
6. 作为用户，我希望新版有自己的应用身份和设置，不影响旧版留白，以便过渡期两者可以并存。
7. 作为用户，我希望新版的导航模式、字体等设置第一次使用时重新选一遍即可，以便不必为几项设置做迁移。

### 笔记库兼容

8. 作为旧版用户，我希望用新版直接打开现有的笔记库文件夹，以便不做任何迁移就能继续写。
9. 作为用户，我希望同一个笔记库文件夹在 Mac 和 Windows 的新版上都能打开，以便我用自己的同步工具在两台电脑之间同步。
10. 作为用户，我希望新版从不改动我的 Markdown 文件，除非是我自己编辑或空间主页按规则写入，以便我的笔记始终是普通文件。
11. 作为旧版用户，我希望新版第一次打开含 `.留白/` 的笔记库时，自动把空间主页、编写说明和操作记录搬进 `.notes/`，以便空间和撤销历史不丢失。
12. 作为旧版用户，我希望搬迁失败时看到明确提示，原来的 `.留白/` 原样保留，以便数据不会因为搬一半而损坏。
13. 作为用户，我希望软件本身不做同步，笔记库放在 iCloud Drive、Dropbox、Syncthing 等同步文件夹里时，它就当普通文件夹读写，以便我自由选择同步方式。
14. 作为用户，我希望同步工具在外部改了笔记时，软件能发现并刷新，正在编辑的笔记被改时走冲突处理，以便同步不会覆盖我没保存的输入。

### 启动性能

15. 作为用户，我希望点开图标后 1 秒内就能在上次打开的笔记里打字，以便想到什么马上能记。
16. 作为用户，我希望关了窗口再打开时 0.3 秒内就恢复，以便频繁开关窗口不用等。
17. 作为有一万篇笔记的用户，我希望启动时不等全库扫描，先显示上次的笔记和当前目录，搜索索引在后台建好，以便笔记多了也不变慢。
18. 作为用户，我希望启动时看不到白屏或转圈，以便打开软件的感觉是干净的。

### 资料库与编辑（对齐基线）

19. 作为用户，我希望新版具备基线规格里的全部资料库能力：资料库导航、单栏导航与双栏导航、当前目录内容、笔记列表、搜索，以便换到新版不少任何功能（“全部笔记”“最近打开”两个入口按界面与动效规格去掉）。
20. 作为用户，我希望新建、改名、移动、移到废纸篓、恢复上次删除，以及改名移动时更新引用，都和旧版一样可靠，以便整理笔记不出错。
21. 作为 Markdown 用户，我希望直接书写 Markdown 并原地看到排版，也能切到源码，以便和旧版的写作方式一致。
22. 作为 Markdown 用户，我希望保存出来的文件和我输入的内容逐字一致，不被编辑器改写列表符号、空行或表格对齐，以便文件在其他编辑器里也一样。
23. 作为用户，我希望代码高亮、表格、行内与独立公式、笔记链接（⌘/Ctrl 点击跳转）、图片与附件（导入、粘贴、拖入）都可用，以便图文和技术笔记照常记录。
24. 作为写作者，我希望列表延续、退出列表、分隔空行的行为与基线规格一致，以便列表输入不出意外。
25. 作为写作者，我希望空行上的插入光标与打出第一个字后的位置和高度一致，文字选区只贴合被选中的文字，以便光标和选区不跳。
26. 作为中文写作者，我希望拼音输入、选区、撤销重做都正常，以便连续写作。
27. 作为写作者，我希望进入和退出专注模式时保留内容、光标、选区和阅读位置，Esc 可以返回，以便不打断思路。
28. 作为用户，我希望保存失败、外部修改冲突时有提示，可以保留输入、重试或另存副本，以便不会静默丢失内容。

### 空间（对齐基线并优化）

29. 作为空间用户，我希望新版具备空间规格里的全部能力：空间、范围、空间主页、记录表、编写说明、操作记录及逐条撤销，以便我的健身、雅思空间照常使用。
30. 作为空间用户，我希望 Agent 之前写好的空间主页不用改就能在新版里运行，以便不必让 Agent 重写一遍。
31. 作为空间用户，我希望空间主页在 Mac 和 Windows 上显示和行为完全一致，以便同一份编写说明在两个平台都有效。
32. 作为让 Agent 写空间主页的用户，我希望编写说明改用与品牌无关的接口名称，以便以后产品改名时空间主页不用跟着改。
33. 作为让 Agent 写空间主页的用户，我希望编写说明附带接口的类型声明，以便 Agent 写出的代码更少出错。
34. 作为空间用户，我希望空间主页里的组件也有入场动效，字体跟随我的排版设置，以便空间主页和笔记的观感一致。
35. 作为空间用户，我希望空间主页仍然只能读写范围内的笔记，每次写入都能撤销，以便 Agent 写错的脚本不会伤到范围外的笔记。

### 动效

36. 作为用户，我希望切换笔记和目录、笔记列表增删与重新排序、选中底板滑动、侧栏折叠与栏宽调整、专注模式进入与退出、搜索框展开与收起、弹出菜单都有弹簧动效，以便操作感觉轻盈连贯。
37. 作为用户，我希望动画中途可以继续操作或反向切换，以便不用等转场结束。
38. 作为写作者，我希望插入光标在位置之间平滑滑动，闪烁是柔和的淡入淡出，以便打字时视线跟得上光标。
39. 作为写作者，我希望新输入的字符轻微淡入，不发生位移，以便打字有手感又不影响阅读。
40. 作为中文写作者，我希望拼音组合过程中也有同样的输入动效，以便中英文输入的体验一致、不割裂。
41. 作为喜欢安静界面的写作者，我希望在设置里分别关闭“光标动画”和“输入动画”，以便按自己的偏好写作。
42. 作为开启了系统“减弱动态效果”的用户，我希望软件遵循这一设置，光标动画和输入动画强制关闭，其余动效降为淡入淡出或直接切换，以便不被动效打扰。
43. 作为用户，我希望界面有通透的层次感（系统原生材质与背景模糊），以便在两个平台上都有轻盈现代的观感。

### 字体与排版设置

44. 作为写作者，我希望正文、标题、代码可以分别选字体，既有预设，也能选系统里安装的任何字体，以便按自己的喜好排版。
45. 作为中文写作者，我希望软件内置一款宋体（思源宋体）和一款英文衬线字体（Source Serif 4），以便在任何电脑上都能用到好看的衬线排版。
46. 作为写作者，我希望能调整字号、行距、段距、版心宽度和标题大小比例，以便得到舒服的阅读密度。
47. 作为中文写作者，我希望中英文之间自动留出空隙，只在显示时生效、不改文件，以便排版好看又不污染 Markdown。
48. 作为用户，我希望排版设置全局生效、存在应用里，不写进笔记库，以便换笔记库也保持同样的阅读体验。
49. 作为用户，我希望默认正文字体仍是系统字体，以便开箱就是熟悉的观感。

### 交付与验收

50. 作为交付验收者，我希望每个里程碑由 CI 在 macOS 和 Windows 上构建安装包并运行自动化测试，以便两个平台的问题都能尽早发现。
51. 作为交付验收者，我希望新版只有在通过三份基线规格和本规格的验收后才取代旧版，以便换版不是倒退。
52. 作为用户，我希望首版不签名、不做自动更新，CI 产出的安装包可以手动安装，以便先自用和小范围分发。

## Implementation Decisions

### 已确认的产品与架构决定

- **完全重写、单一代码库**：用 Electron + TypeScript 重写，macOS 与 Windows 共用同一套代码、功能一致。选 Electron 而不选 Tauri 2 或 Flutter，是因为空间主页由 Agent 自由编写，各平台都用 Chromium 才能保证同一份编写说明的效果一致（ADR 0004）。
- **平台优先级**：以 macOS 为主，日常开发和测试在 macOS 上进行；Windows 为辅，由 CI 构建测试，发布前人工走查关键流程；Linux 与移动端不在本次范围内。
- **界面框架与动效**：React，动效统一用 Motion 的弹簧动画，动效是需要重点打磨的部分。
- **编辑器内核**：CodeMirror 6。直接编辑 Markdown 源文本，用装饰实现原地排版，源码切换是同一文档的另一种显示方式。不采用 ProseMirror 一类所见即所得模型，因为它们在保存时转换回 Markdown，无法逐字保真。
- **自包含目录**：新版位于仓库根目录的 `notes-desktop/`，不依赖仓库其他目录，可以整体移出成为独立项目；术语表、ADR 和规格位于该目录的 `docs/` 内。
- **开发代号与命名**：开发期间使用中性代号 `notes-desktop`。产品新名称采用“物品名词 + 笔记”的形式（类似“水滴笔记”），待用户另行确定；到时集中替换应用名和文案，不涉及笔记库格式和空间接口。
- **笔记库格式**：同一文件夹在任何平台、任何版本都能打开；Markdown、附件、记录表格式不变。
- **隐藏目录**：应用自用数据存放在笔记库的 `.notes/`（空间主页、编写说明、顺序配置、操作记录），取代 `.留白/`。首次打开含 `.留白/` 且不含 `.notes/` 的笔记库时自动搬迁；搬迁中途失败不能损坏原目录。搬迁后旧版将看不到空间，用户已接受。
- **同步**：应用不做同步，也暂不针对 iCloud Drive 做专门优化。同步带来的外部修改依靠文件监视发现，正在编辑的笔记走现有的冲突处理。
- **空间接口**：保持旧接口的全部能力和权限语义（ADR 0002、0003）。接口、组件、样式变量、meta 改用与品牌无关的新前缀，具体名称在实现时确定并写进编写说明；原 `lb` 系列名称（`lb` 对象、`lb-*` 组件、`--lb-*` 变量、`lb-scope`/`lb-icon` meta）作为兼容别名永久保留，已有空间主页无需修改。编写说明附带接口的 TypeScript 类型声明，路径改为 `.notes/`。组件接入 Motion 入场动效和排版设置。
- **空间主页的运行环境**：空间主页在独立的沙盒环境中运行，与应用界面隔离，每个空间各自拥有隔离的持久化存储，允许联网；页面只能通过桥接接口访问笔记，所有校验和执行都在主进程的核心库中完成，桥接层不含业务逻辑。
- **视觉效果**：不再使用 Metal。通透质感由系统原生窗口材质与应用内背景模糊共同实现，详见 [界面与动效规格](ui-motion-spec.md)；用 WebGL 模拟折射是以后的打磨任务，不在本次对齐范围内。配色与深色模式见界面与动效规格。
- **动效范围**（分级与四种动效预设见 [界面与动效规格](ui-motion-spec.md)）：切换笔记和目录、笔记列表增删与重新排序、选中底板滑动、侧栏折叠与栏宽调整、专注模式进入与退出、搜索框展开与收起、弹出菜单、空间主页卡片入场。所有转场都可以中途打断或反向，输入、保存、搜索不等待动画。实现后做专项审查。
- **输入动效**：插入光标在位置之间平滑滑动，闪烁改为淡入淡出；新输入的字符约 100 毫秒淡入、不位移；拼音组合中的文本也有同样的动效。“光标动画”“输入动画”是两个独立开关，默认开启；系统开启“减弱动态效果”时强制关闭。
- **减弱动态效果**：遵循系统设置，其余动效降为淡入淡出或直接切换。
- **排版设置**：全局一套，存在应用设置中，不写进笔记库。可调项包括正文/标题/代码字体（预设加系统已安装字体）、字号、行距、段距、版心宽度、标题大小比例、中英文自动间距（仅显示，不改文件）。默认正文字体是系统字体（macOS 苹方/SF，Windows 微软雅黑/Segoe UI），等宽字体用平台默认。空间主页通过样式变量使用同样的字体和字号。
- **内置字体**：随应用分发思源宋体（简体，常规与半粗两个字重）和 Source Serif 4（可变字重），作为排版设置的可选预设；两者都是 OFL 许可，需附带许可文件。
- **平台习惯**：⌘ 对应 Ctrl；macOS 使用隐藏式标题栏、保留红绿灯按钮和系统菜单栏；Windows 使用自绘标题栏、系统窗口按钮和窗口内菜单按钮。
- **启动性能目标**（以 Apple M4 Mac、约一万篇笔记的笔记库为准）：冷启动到能在上次打开的笔记里打字不超过 1 秒；关闭窗口后再次打开不超过 0.3 秒；启动不等待全库扫描或索引，搜索索引在后台建立；不出现白屏或转圈的启动画面。Windows 上同样的数值只作参考，不作为验收门槛。
- **分发**：首版不签名、不公证、不做自动更新，CI 产出 macOS 与 Windows 安装包。

### 模块

- **核心库（深模块，主要测试接缝之一）**：纯 TypeScript，只依赖 Node 的文件系统能力，不依赖 Electron 和界面。对外提供笔记库的打开与刷新、库内路径校验、笔记与文件夹的增删改移（删除进系统废纸篓）、改名移动时的引用更新、Markdown 结构解析、记录表读写、空间库（发现、解析 meta、新建、顺序、提示词、编写说明）、空间请求处理（一条结构化请求进、JSON 结果或结构化错误出）、操作记录与逐条撤销、`.留白/` 搬迁、文件监视、搜索索引。行为以旧版 `NotesCore` 为准逐项移植。
- **主进程**：创建窗口、平台菜单与快捷键、设置存储、把核心库能力通过进程间接口暴露给界面，把空间请求从空间主页转交核心库。不含业务逻辑。
- **界面（渲染进程，React + Motion）**：资料库导航、单栏/双栏导航、笔记列表（含就地搜索）、专注模式、空间界面、操作记录面板、设置（含排版设置和两个动画开关）。
- **编辑器（CodeMirror 6 扩展集合）**：Markdown 原地排版装饰、源码切换、列表延续与退出列表、分隔空行显示、自绘插入光标与输入动效、文字选区绘制、代码高亮、表格与公式显示、笔记链接、图片与附件的插入。
- **空间主页运行环境**：沙盒页面、样式包、组件、兼容别名、桥接脚本、错误条与写入提示。

### 对基线的修订

- 基线 [spec](spec.md) 中“macOS 原生应用、SwiftUI/AppKit/Metal、真实 Metal 效果验收”的决定与验收项，由本规格的 Electron、模糊材质和动效决定取代。
- 基线 Out of Scope 中“专门适配系统减少动态效果”的排除被撤销：新版遵循该设置。
- 基线 Out of Scope 中“Windows 与 Linux 首版”的排除被修订：Windows 属于范围内，Linux 仍不在范围内。
- 基线 [spec](spec.md) 的“查看最近打开”及资料库导航中的“全部笔记”“最近打开”入口被去掉，见 [界面与动效规格](ui-motion-spec.md)。
- 基线 Out of Scope 中“打字粒子”一类装饰仍然排除；本规格的光标和输入动效是克制的淡入与滑动，不属于装饰动画。
- 基线 [spaces-spec](spaces-spec.md) 中 `.留白/` 路径、WKWebView 和 FSEvents 等实现细节，由本规格的 `.notes/`、沙盒页面和跨平台文件监视取代；空间的产品语义不变。

### 里程碑

1. **骨架**：Electron 应用、打开笔记库、资料库导航与笔记列表、CodeMirror 编辑与自动保存、两平台 CI。
2. **编辑对齐**：原地排版、列表延续与退出列表、插入光标、文字选区、表格与公式、链接与附件、专注模式、外部修改冲突、排版设置与内置字体、输入动效。
3. **空间**：空间主页、记录表接口、操作记录、新接口前缀与兼容别名、类型声明、`.留白/` 搬迁。
4. **完成对齐**：Windows 适配、动效打磨与专项审查、大胆高饱和外观风格、启动性能达标、按三份基线规格和本规格完整验收，然后取代旧版。

## Testing Decisions

- **好测试的标准**：只测外部行为，即对临时笔记库操作后看到的结果、磁盘上的 Markdown 和隐藏目录内容，以及界面上用户可见的状态。不依赖内部函数、组件层级或私有状态，不 mock 文件系统。
- **接缝 A：核心库**（已与用户确认）。用 Vitest 对真实临时笔记库调用核心库的公开接口。旧版 `NotesCoreTests` 的用例（工作区、记录表、空间请求处理、空间库、操作记录、引用更新、文件监视、渲染语法）逐条移植作为对齐证据，再加上 `.留白/` 搬迁（正常、部分已存在、中途失败）、兼容别名下的请求、万篇笔记库的启动路径不做全量扫描等新用例。
- **接缝 B：运行中的应用**（已与用户确认）。用 Playwright 驱动 Electron 应用打开临时笔记库，覆盖编辑与列表行为（对应旧版 `EditorWorkflowTests`、`ListEditingTests`）、插入光标与文字选区的几何位置、拼音组合输入、专注模式、外部修改冲突、空间工作流（对应旧版 `SpaceWorkflowTests`）、已有旧空间主页原样运行、设置开关与减弱动态效果，以及冷启动和再次打开的耗时测量。
- **暂不设第三个接缝**：列表编辑的边界情况多，如果接缝 B 太慢，再考虑直接对编辑器状态执行命令的测试，不预先建立。
- **CI**：两个接缝都在 macOS 和 Windows 上运行；每个里程碑产出两个平台的安装包。
- **人工验收**：动效手感、输入动效在真实输入法下的表现、字体渲染、Windows 上的关键流程需要人工在真实应用里检查并记录证据；构建成功和测试通过不能代替体验验收。启动性能要记录机器、系统、笔记库规模和测量方式。
- **风险点**：拼音组合文本由系统输入法与编辑器共同绘制，给它加动效最容易出现抖动、错位或丢字，需要在 macOS 与 Windows 的系统拼音输入法下分别专项验证。

## Out of Scope

- Linux 版、移动端（iOS、iPadOS、Android）、网页版。
- 内置同步、账号、云服务；针对 iCloud Drive 的专门优化（如未下载文件的处理）。
- 代码签名、苹果公证、Windows 签名证书、自动更新、公开发布渠道。
- 产品正式命名与品牌设计（另行决定）。
- 用 WebGL 模拟折射等超出模糊材质的视觉特效。
- 按笔记库或按单篇笔记的排版设置。
- 旧版设置（导航模式、字体、入口显示）的迁移。
- 旧版 `NotesLite/` 的新功能开发。
- 基线规格中仍然有效的排除项：内置 Agent 与模型调用、为外部 Agent 提供控制接口、多人协作、图谱等。

## Further Notes

- 本规格与三份基线规格一起构成验收范围。拆分任务时，基线规格中已经由旧版实现并验证的行为，按“移植 + 对齐验收”拆分，不重新设计。
- 新接口前缀的具体名称、动效参数、输入动效的实现方式（自绘光标层、字符淡入的装饰方式）都是实现时确定的工程细节，不是用户已确认的决定；确定后写进编写说明或动效规格。
- 旧版规格中链接到 `NotesLite/evidence` 和 `.scratch` 的历史验收记录位于 `notes-desktop/` 之外，整体移出仓库前需要处理。
