# 界面与动效规格

日期：2026-10-19。状态：已定稿。方向与各项决定已与用户逐条确认，并经可交互原型校准；具体取值见 [设计规范](../design-system.md)。上位规格：[跨平台桌面版重写规格](desktop-rewrite-spec.md)。

## Problem Statement

新版是一个全新产品，名字和技术栈都要换。旧版的界面结构经过几轮实际使用，已经确认可用；但视觉语言是为 macOS 原生和 Metal 设计的，到 Electron 上不能照搬。用户希望新版的界面和动画比旧版更讲究，动画要着重打磨，同时不能让高频操作变慢、变吵。

## Solution

沿用旧版的界面结构：三栏资料库、单栏导航与双栏导航、专注模式、“资料库 | 空间”切换。视觉语言重新设计，走**通透现代**方向：窗口底层用系统原生材质，侧栏与笔记列表铺在材质上，正文是一张浮起的圆角卡片。动效分级：越常用的操作越轻快，越少用的操作越有表现力，所有界面只使用四种动效预设。

设计经可交互的 React + Motion 原型比较三个视觉变体后定稿：采用原生材质版，默认动效强度为“强”。

## User Stories

1. 作为用户，我希望新版保留熟悉的三栏结构、导航模式和专注模式，以便换版后不用重新学。
2. 作为用户，我希望窗口有通透的层次感，桌面的颜色能透进侧栏，以便软件看起来轻盈、现代。
3. 作为写作者，我希望正文区始终不透明或接近不透明，以便长时间阅读对比度足够。
4. 作为用户，我希望正文像一张浮起的卡片，导航退在背景里，以便视线自然落在正文上。
5. 作为 Windows 10 用户，我希望没有系统材质时界面退回纯色，依然好看可用。
6. 作为用户，我希望强调色默认跟随系统，也可以在设置里从几种预设中选，以便符合自己的喜好。
7. 作为用户，我希望强调色只出现在插入光标、文字选区、开关和主要按钮上，以便通透的界面保持干净。
8. 作为用户，我希望深色模式是单独设计的，不是简单反色，也可以在设置里固定为浅色或深色。
9. 作为用户，我希望笔记列表默认只显示标题，以便一屏能看到更多笔记。
10. 作为用户，我希望在设置或笔记列表的“…”菜单里把列表切换为简洁、标准、详细三档，以便按需要查看日期和摘要。
11. 作为用户，我希望选中项有一块半透明的胶囊底板，切换时带轻微回弹滑过去，图标从线性变为实心，以便清楚看到当前位置。
12. 作为用户，我希望悬停列表行时只出现淡淡的底色，不会一排排浮起，以便界面不吵。
13. 作为用户，我希望按下按钮和列表项时有轻微缩小再弹回的反馈，以便确认操作被接收。
14. 作为写作者，我希望正文卡片顶部只有路径，操作按钮在鼠标靠近时浮现、打字时隐藏，以便写作时界面安静。
15. 作为写作者，我希望字数和保存失败在卡片底部以低显著度显示，以便需要时看得到、平时不打扰。
16. 作为用户，我希望在列表里往下选笔记时，新内容从下方淡入，往上选时从上方进来，以便感知自己在列表中移动的方向。
17. 作为用户，我希望用方向键快速连续切换笔记时动画立即中断，绝不排队，以便切换速度不受动画拖累。
18. 作为写作者，我希望进入专注模式时正文卡片以弹簧动画放大铺满窗口，侧栏和列表像抽屉一样整体向左推出，背景材质变暗但仍在，以便有一种沉入写作的空间感。
19. 作为写作者，我希望退出专注模式时卡片缩回原位，以便知道自己回到了哪里。
20. 作为用户，我希望按 ⌘K / Ctrl+K 或点击笔记列表顶部的搜索条时，搜索条就地变成搜索框，结果直接显示在列表里，Esc 恢复原来的列表，以便搜索不打断当前的界面。
21. 作为空间用户，我希望在“资料库 | 空间”之间切换时，分段控件的底板滑过去，侧栏内容随之左右平移，以便知道自己进入了另一个区域。
22. 作为空间用户，我希望空间主页和笔记之间切换，以及空间主页卡片入场时，都有浮现动效。
23. 作为用户，我希望设置是一张浮在主窗口上的玻璃面板，在两个平台上观感一致。
24. 作为写作者，我希望排版设置页右边用当前打开的笔记做实时预览，调整时预览带动效同步变化，以便所见即所得地调出喜欢的排版。
25. 作为用户，我希望所有界面的动效手感统一，以便软件感觉是一个整体。
26. 作为开启了系统“减弱动态效果”的用户，我希望所有动效降为淡入淡出或直接切换。
27. 作为用户，我希望设置界面层级清晰、分组明确，数值用滑块等可视化控件调整并立即看到效果，以便不用猜每个选项的作用。

## Implementation Decisions

### 已确认的设计决定

- **结构沿用、视觉重做**：三栏资料库、单栏/双栏导航、专注模式、“资料库 | 空间”切换沿用旧版语义；配色、材质、字体层级、图标、圆角、阴影重新设计。
- **视觉方向**：通透现代。
- **材质**：混合实现。窗口底层用系统原生材质（macOS 为 vibrancy，Windows 11 为 Mica/Acrylic），Windows 10 退回纯色；菜单、对话框等浮层用应用内背景模糊。正文区不透明或接近不透明。设置改为独立窗口，用与主窗口相同的窗口材质，可移动、可关闭（2026-10-21 用户反馈：浮在窗口上的玻璃设置面板与主窗口背景风格割裂；取代原“设置面板”浮层的做法，下文的“设置面板”均指这个窗口，它的打开不再有浮现动效，由系统的窗口动画呈现）。
- **窗口版式**：侧栏与笔记列表铺在材质上；正文是一张浮起的圆角卡片，带柔和阴影。正文卡片右侧预留可折叠的**助手栏**（里程碑 5），打开时卡片变窄，左侧导航按窗口宽度逐级收为单栏或图标栏（见助手栏规格），不使用浮动面板；助手栏收起时卡片右上角显示助手形象按钮。助手栏与助手形象见 [助手栏规格](assistant-spec.md)。
- **强调色**：默认跟随系统强调色，设置中可从预设中选择。背景渐变只用低饱和的柔和色调。强调色只用于插入光标、文字选区、开关和主要按钮。
- **深色模式**：默认跟随系统，设置中可固定为浅色或深色；深色模式单独设计。
- **图标**：Phosphor。默认线性风格，选中态切换为实心。
- **笔记列表详细程度**：三档。简洁（只有标题，默认）、标准（标题加弱化日期）、详细（标题、一行摘要、日期）；搜索结果始终显示所属路径。入口在设置和笔记列表顶部的“…”菜单。
- **选中态**：白色胶囊底板（侧栏略透明；深色模式为半透明浅灰），细描边加贴近的阴影，边缘清楚而不是一块发虚的白色；以“滑移”移动并带轻微回弹，跨越超过 5 行时改为淡出淡入；Phosphor 图标同时由线性淡入为实心。
- **侧栏**：不提供“全部笔记”“最近打开”入口，也不显示“资料库”分组标题；侧栏只有“文件夹”分组，默认选中一个文件夹。“文件夹”分组标题右侧不放按钮（搜索在笔记列表顶部；单栏导航时“笔记”标题右侧是搜索按钮），没有全局新建按钮；新建笔记通过 ⌘N（在当前文件夹中）或文件夹行悬停时浮现的新建图标。
- **文件夹点击**：点击未选中的文件夹会选中并展开；再次点击已展开的选中文件夹会收起，再点又展开。展开箭头仍只控制展开状态。
- **在文件夹中新建**：鼠标悬停在文件夹行上时，行尾浮现新建图标，点击即在该文件夹中新建笔记。
- **外观风格**：设置中可选“原生材质”（默认）或“大胆高饱和”。两种风格共用同一套设计变量，只是取值不同；空间主页随之切换。大胆高饱和在里程碑 4 实现，配色需另行打磨。
- **正文卡片工具栏**：顶部不再显示路径（笔记所在位置放到标题的悬停提示里）；操作按钮在鼠标悬停顶部区域时浮现、打字时隐藏；底部低显著度显示字数，保存失败或冲突时在左侧显示原因与重试（“已保存”“正在保存…”不显示，只供读屏朗读；2026-10-21 用户反馈决定）；搜索、新建等全局操作移到侧栏顶部。
- **笔记标题**（2026-10-21 用户反馈决定，方案 A，同 Obsidian 的内联标题）：正文上方显示笔记文件名（不含 .md），字号字重同一级标题，随正文滚动；点击即可修改，回车或离开即按“重命名…”的规则改名，Esc 还原；回车与 ↓ 进入正文开头；名称为空或无法使用时在下方说明原因并还原旧名。标题不写入文件内容。
- **专注模式**：正文卡片以克制的弹簧放大铺满窗口（即使在“强”档下回弹也很小，用户要求整卡展开的动效弱一些），侧栏和列表整体向左推出窗口、不淡出，卡片跟着向左扩展填满（2026-10-21 用户反馈决定，方案 B；取代此前的淡出并左移几像素，那样侧栏还没淡完卡片就盖上去，文字叠在一起）；背景材质保留并变暗；标题和正文按排版设置的版心宽度居中；右上角低显著度退出按钮，Esc 返回；退出时卡片缩回原位。
- **搜索**：不做命令面板，也不弹出浮层。⌘K / Ctrl+K 或笔记列表顶部常驻的搜索条（显示“搜索 ⌘K”）让搜索条就地展开为搜索框（双栏导航；单栏导航仍是侧栏“笔记”旁的搜索按钮，2026-10-21 用户反馈决定）；结果以列表形式显示并带所属路径，默认搜索全库，可切换为当前文件夹及子文件夹；打开结果会定位到所属目录；Esc 或清空后恢复原来的列表。（取代此前“搜索与命令面板”的决定。）
- **设置**：应用内浮起的玻璃面板，不使用独立的系统窗口。层级清晰：左侧分类，右侧按分组排列，每组有标题和简短说明，组内项目对齐、间距一致；数值项一律用可视化控件（滑块带实时数值、分段控件、色板、开关、带预览的选项），不用纯文本输入（用户要求）。排版设置页左侧是选项，右侧用当前笔记做实时预览，预览随调整带动效变化。
- **“资料库 | 空间”切换**：分段控件底板以“滑移”移动；侧栏内容横向平移，进入空间向左，返回资料库向右；右侧卡片在空间主页与笔记之间以“浮现”切换。

### 动效

- **分级原则**：
  - 高频操作（悬停、选中、列表滚动、打字与光标）短促，带轻微回弹，不拖慢操作；
  - 中频操作（切换笔记、展开文件夹、侧栏折叠）有明显的滑动和弹性；
  - 低频操作（专注模式、设置窗口（由系统的窗口动画呈现）、新建空间、首次打开笔记库）最有表现力，允许轻微形变和层次变化。
- **四种动效预设**，所有界面及空间主页组件只使用这四种，参数集中定义在设计规范中，改一处全局生效：
  - **轻弹**：悬停、按压、选中、图标线性变实心。最短促，带轻微回弹。
  - **滑移**：选中底板、列表增删与重排、栏宽调整、插入光标移动。位移明显，回弹小；即使动效强度调高，选中底板切换时的回弹也保持很小。
  - **展开**：文件夹展开、侧栏折叠、菜单与下拉。尺寸变化，带轻微形变。
  - **浮现**：对话框、空间主页卡片入场、空间主页与笔记切换。缩放、模糊、不透明度组合，最有表现力。
- **动效强度**：设置的“动画”页提供轻、标准、强三档，**默认“强”**。强度只明显放大低频与中频动效（展开、浮现及转场距离）；轻弹与滑移这类高频动效在“强”档下回弹最多比标准高约 15%，选中底板始终保持轻快。
- **输入动画**（字符淡入）单独实现，不属于四种预设；行为见上位规格。
- **悬停与按压**：悬停只加淡底色，不浮起；按压缩小到约 0.97 倍后回弹。卡片、按钮等独立元素悬停时可以轻微浮起并加阴影。
- **切换笔记**（2026-10-21 用户反馈决定，取代此前“有方向的过渡”）：卡片本身不动，只替换内容；新内容约 0.12 秒淡入，同时上移约 4 像素（标准档）。选中底板相距不超过 5 行时滑过去；更远时旧位置的底板淡出、新位置的底板从略小处放大淡入，不再长距离滑过中间的行。图标由线性变实心、文字变粗时淡入淡出，不瞬间跳变。连续切换时立即中断上一段动画，不排队。
- **可打断**：所有转场都可以中途打断或反向；输入、保存、搜索不等待动画。
- **减弱动态效果**：遵循系统设置，四种预设降为淡入淡出或直接切换，光标与输入动画关闭。

### 设计流程与结果

- 用 React + Motion 做了一次性可交互原型，比较三个视觉变体：原生材质、渐变磨砂、大胆高饱和，并提供动效强度、深浅色和减弱动态效果的切换。原型只覆盖主窗口（含就地搜索）、专注模式和带实时预览的排版设置，使用内存中的示例笔记。
- 结果：采用**原生材质版**；默认动效强度为加强后的“强”档；大胆高饱和保留为里程碑 4 的可选外观风格，配色重新打磨；渐变磨砂版不采用。
- 原型校准期间的修改都已写入上文决定：搜索改为就地搜索、去掉“全部笔记”“最近打开”和全局新建按钮、文件夹点击切换展开、悬停在文件夹中新建、笔记列表与侧栏拉开对比、选中底板加细描边、路径文字加深、高频动效的回弹不随强度放大。
- 定稿取值写入 [设计规范](../design-system.md)。原型代码在提交 `a40a0ac` 中留档，正式实现开始前从工作目录删除，不进入正式代码。

### 设计范围与优先级

全部界面都要设计。以下 1–4 先做，用来确立视觉语言；5–10 沿用已确立的语言：

1. 主窗口（双栏导航、单栏导航、窄窗口图标栏）
2. 专注模式
3. 就地搜索
4. 设置窗口（含带实时预览的排版设置）
5. 空间界面（空间列表、空间主页、新建/编辑空间）
6. 操作记录面板
7. 首次启动与空状态（选择笔记库、空文件夹、无搜索结果）
8. 右键菜单与弹出菜单
9. 提示与对话框（保存失败、外部修改冲突、空间写入提示、搬迁失败）
10. Windows 标题栏与窗口内菜单

## Testing Decisions

- 动效手感、材质观感、深浅色效果只能由用户在原型和真实应用中判断，不以自动化测试代替。
- 正式实现后，接缝 B（运行中的应用）检查可验证的行为：列表三档详细程度的显示、就地搜索的结果与恢复、设置面板的打开与实时预览、专注模式往返后的编辑位置、减弱动态效果下动效被关闭、快速连续切换笔记时界面最终状态正确且不卡住。
- 每种动效预设在 [设计规范](../design-system.md) 中有明确参数，人工验收时对照检查。

## Out of Scope

- 首次启动欢迎页的插画风格、应用图标和品牌设计（等产品名称确定后再定）。
- 以 WebGL 模拟折射等超出系统材质与背景模糊的效果。
- 声音反馈。
- 命令面板（用户明确不要）。
- 原型中的渐变磨砂版，以及最初设想的克制版（只在浮层用玻璃），均未采用。
- 提前实现大胆高饱和外观风格（排在里程碑 4）。

## Further Notes

- 原型中原生材质无法真实还原，最终观感要在 Electron 真实窗口中复核，尤其是 Windows 11 Mica 与 macOS vibrancy 的差异；复核后如需调整，只改设计规范中的取值。
- 光标动画与输入动画（含拼音组合）的参数尚未确定，需在 CodeMirror 编辑器原型中校准后补入设计规范。
- 本规格修订了上位规格中“玻璃质感用半透明模糊材质”的表述，具体见上位规格。
