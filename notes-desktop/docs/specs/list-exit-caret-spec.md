# 退出列表与空行插入光标规格

日期：2026-10-19。适用产品为留白（`NotesLite/`）。决策来源：2026-10-19 用户录屏反馈后的设计追问，全部决定已获用户确认。术语见 [术语表](../GLOSSARY.md)。

## Problem Statement

在正文里写列表和空行时，有两处操作感觉割裂：

1. **退出列表多出一行。** 在列表末尾回车后得到一个新的空列表项，再回车想结束列表，标记消失的同时光标又被推到下面第二行，相当于“退出列表”和“换行”同时发生。用户只想退出，不想换行。
2. **空行上的插入光标偏低。** 光标停在空行上时比正常文字行低一截；一开始打字（包括中文输入法组字），光标就上移，造成跳动。

另外，嵌套的空列表项回车时直接整段退出列表，而不是先回到上一层级。

## Solution

- 在最外层空列表项上回车：只移除标记，光标留在原行，不换行。为了让 Markdown 文件在其他编辑器里依然把后续内容视为独立段落，等用户真正在这一行开始输入时，编辑器才在列表与这一行之间补上一个分隔空行；夹在列表和紧随其后的普通段落之间的这一个空行显示得很矮，因此补空行时文字不发生位移。
- 在嵌套空列表项上回车：退回上一层级，标记跟随父项。
- 空行上的插入光标与在该行打出第一个字之后的位置和高度完全一致，输入时零位移。

## User Stories

1. 作为写作者，我希望在最外层空列表项上回车时只移除列表标记，以便结束列表后直接在同一行继续写正文。
2. 作为写作者，我希望退出列表后光标不往下跳，以便操作连贯、不被打断。
3. 作为写作者，我希望退出列表对无序列表（`-`、`*`、`+`）生效，以便常用列表都能顺手结束。
4. 作为写作者，我希望退出列表对有序列表生效，以便编号列表也能同样结束。
5. 作为写作者，我希望退出列表对任务列表生效，以便待办清单也能同样结束。
6. 作为写作者，我希望退出列表后在这一行开始输入正文时，保存的 Markdown 自动在列表与正文之间留出空行，以便在其他 Markdown 编辑器或网站打开时正文不会并入上一个列表项。
7. 作为写作者，我希望自动补空行时正在输入的这一行不发生上下位移，以便打第一个字时界面保持稳定。
8. 作为中文写作者，我希望输入法开始组字的那一刻就按“开始输入”处理，以便拼音尚未上屏时也不出现跳动或错误的分隔。
9. 作为写作者，我希望粘贴非空内容也按“开始输入”处理，以便粘贴的正文同样与列表正确分隔。
10. 作为写作者，我希望退出列表后若只是把光标移开、这一行保持为空，就不自动补空行，以便文件里不残留多余空行。
11. 作为写作者，我希望退出列表后在这一行重新输入完整的列表标记（例如 `- `、`1. `、`- [ ] `）时，自动补的空行被去掉，以便新列表紧接上方列表、不被空行隔开。
12. 作为写作者，我希望只敲了 `-` 还没敲空格时，分隔空行仍然保留，以便以连字符开头的正文不被误判为列表。
13. 作为写作者，我希望把这一行的字全部删掉回到空行时，自动补的空行也一并去掉，以便回到刚退出列表的状态、光标不往下跳。
14. 作为写作者，我希望在嵌套的空列表项上回车时退回上一层级、对齐父项缩进，以便逐级结束嵌套列表。
15. 作为写作者，我希望退回上一层级的项沿用父项的标记类型，以便同一层级的标记保持一致。
16. 作为写作者，我希望从有序子列表退回时编号接在父项之后，以便编号延续父层的顺序。
17. 作为写作者，我希望从任务子列表退回到任务父项时新项是未勾选的待办，以便继续添加待办。
18. 作为写作者，我希望退回上一层级时编辑器不自动给后面的项重新编号，以便行为与现有列表延续一致、不意外改动其他行。
19. 作为写作者，我希望在最外层空项上退出列表时才真正结束列表，以便嵌套层级逐级退出、行为可预期。
20. 作为写作者，我希望撤销按系统正常的粒度逐步回退，以便连续按 ⌘Z 能一步步回到之前的状态。
21. 作为写作者，我希望补空行和去掉空行与触发它们的那次输入在同一个撤销步骤内，以便撤销时不出现看不见的空行导致光标跳动。
22. 作为写作者，我希望打开已有笔记时，夹在列表与紧随其后的普通段落之间的那一个空行同样显示得很矮，以便同样的源码始终呈现一致。
23. 作为写作者，我希望在列表后连敲两个空行时仍能看到正常的空白，以便需要时保留明显的视觉间隔。
24. 作为写作者，我希望在代码块里回车不触发列表延续或退出列表，以便代码内容保持原样。
25. 作为写作者，我希望在段落之间的空行上，插入光标与在该行打出第一个字后的位置和高度一致，以便输入时光标不跳动。
26. 作为写作者，我希望在文档末尾的空行上，插入光标同样与打出第一个字后的位置和高度一致，以便在文末续写时光标稳定。
27. 作为写作者，我希望刚退出列表后的那一行上，插入光标与打出第一个字后的位置一致，以便退出列表后立即输入不跳动。
28. 作为中文写作者，我希望在空行上开始输入法组字时插入光标不发生纵向位移，以便组字过程平稳。
29. 作为写作者，我希望空行上的插入光标高度与正文字号匹配，不因行距被拉长，以便与有字的行保持一致的视觉。
30. 作为写作者，我希望保存后重新打开笔记，列表、分隔空行与正文都与编辑时一致，以便确认 Markdown 保真。

## Implementation Decisions

- **退出列表的源码结果**：最外层空列表项回车时，删除该行的列表标记（含缩进），不插入换行。光标留在该行行首。现有“把标记替换为换行”的行为作废。
- **分隔空行（延迟补入）**：光标所在行为空、且紧接在列表项（非代码块内）之下时，该行出现第一个字符——包括输入法开始组字、键入、粘贴非空内容，不含换行——即在这一行之前插入一个空行，使源码成为“列表项、空行、正文”。只移动光标离开或保持为空不补。补入条件由文本本身判断而非记忆“刚退出”的状态，因此撤销、切换笔记后行为一致（2026-10-19 审查后调整）。编辑器只记住自己补入的那一个分隔空行，光标离开其下一行、切换笔记或撤销重做时不再追踪。
- **分隔空行（撤回）**：当该行开头构成完整的列表标记（以标记后的空格为准），或该行被删空时，撤回之前补入的分隔空行。只有标记字符、尚未有空格时不撤回。
- **撤销粒度**：沿用系统正常的撤销粒度，不为退出列表专门合并或拆分步骤。补入和撤回分隔空行必须与触发它的那次输入处于同一撤销分组，不能单独成为一步。
- **嵌套空项退一级**：嵌套的空列表项回车时，缩进改为与父项一致，标记改为父项的类型：无序沿用父项的符号；有序取父项编号加一并沿用父项的分隔符（`.` 或 `)`）；任务列表生成未勾选的任务标记。后续同级项不重新编号。退一级不补分隔空行（仍在列表内）。
- **列表与段落间空行的显示**：排版时，紧接在列表项之后、紧接在普通段落之前的那一个空行，以极小的行高显示，仅保留段落已有的间距；该规则对所有笔记一致生效，与空行来源无关。列表与段落之间有两个及以上空行时，不满足“同时紧邻两者”，全部按正常空行显示。源码保持不变。
- **空行插入光标**：空行上的光标纵向位置与高度，按该行将要输入的正文排版（当前输入属性）计算，使其与打出第一个字后的光标在 0.6 点误差内重合；覆盖段落间空行、文档末尾的额外行、刚退出列表的行以及输入法组字开始。水平位置仍取自 AppKit。
- **涉及模块**：原生编辑器的换行处理与输入拦截（退出列表、退一级、分隔空行补入与撤回）；退一级时由编辑器向上找到父项，再用 Markdown 核心现有的列表延续计算得出父项的下一项标记（核心接口未改）；样式器的空行行高规则（光标所在的分隔空行照常显示，以便光标可见）；插入光标几何计算。
- **范围约束**：代码块、公式块等字面块内不触发上述任何行为；输入法组字期间不执行退出列表（沿用现有判断）。现有“退出列表后忽略输入法立即回显列表标记”的保护保留。

## Testing Decisions

- **唯一测试接缝**：真实 SwiftUI 窗口与 AppKit 编辑器，配合临时笔记库，与现有原生编辑测试相同，不使用编辑器模拟。只通过原生文字输入动作驱动：换行、插入文本、设置组字文本、退格、粘贴、编辑器自带撤销管理器。
- **只断言外部行为**：编辑器源码字符串与选区、插入光标矩形、各行在屏幕上的纵向位置（用于零位移和空行压矮），以及保存后磁盘上的 Markdown。不为内部函数或调用关系编写镜像测试；Markdown 核心不另设单元测试。
- **需覆盖的场景**：三种列表的最外层退出；退出后打字、组字、粘贴补空行且该行零位移；重新输入完整列表标记撤回空行，只输入 `-` 不撤回；删空撤回；嵌套无序、有序、任务列表退一级及编号；撤销逐步回退且无单独的空行步骤；打开已有含“列表、空行、段落”的笔记时空行被压矮；四种空行场景的光标零位移；保存并重新读取后的源码。
- **先有失败**：修复前，退出列表结果与空行光标断言应失败，修复后通过；现有断言 `- 项目\n\n` 的测试改写为新行为。
- **已有先例**：原生编辑测试中的光标几何、导航、组字与退出列表测试，以及打字时光标移动经过原生排版与重排的测试。

## Out of Scope

- 列表的 Tab / Shift-Tab 缩进操作。
- 自动重新编号有序列表。
- 引用块（`>`）及引用内列表的延续与退出。
- 插入光标的动画、颜色或宽度调整。
- 原产品共笔的编辑器。

## Further Notes

- 选择“延迟补空行 + 压矮显示”而非“直接写两个换行”，是为了同时满足“只取消、不换行”的操作感和 Markdown 在其他编辑器中的保真（标准 Markdown 中，紧贴列表项、无空行分隔的文字会被视为该项的续行）。
