# 35: 强大的排版功能（后续更新）

**What to build:** 在应用里内置一套“排版”能力：把笔记排成可以打印、分享的成品（分页、版式、导出 PDF 等），而不只是现在屏幕上看笔记的字体字号（任务 16 已做）。具体做到哪一步还没定。

**Blocked by:** 无（2026-10-22 用户要求先不做，写进后续更新计划，届时再拷问细节）

**Status:** later（后续更新，未进入排期）

## 背景

2026-10-22 用户问：“想在这个软件中内置一个强大的排版功能，大概需要怎么做？是个什么东西？”准备用 hero-grill-with-docs 逐条敲定，刚开始就决定先不做。

现状：任务 16 的排版设置只管屏幕上的阅读（正文、标题字体，字号、行距、段距、版心宽度、标题比例，中英文间距），内置思源宋体与 Source Serif 4。没有分页，也不能导出。

## 届时要先定的问题

1. 排版为了什么：打印或导出 PDF（作业、报告、论文），还是在屏幕上把一篇笔记排得更好看，还是两者都要？
2. 排版的单位：一篇笔记，几篇笔记拼成一份文档，还是整个文件夹（例如一本书）？
3. 版式要多少：纸张与页边距、页眉页脚与页码、目录、脚注、图表编号与交叉引用、参考文献、分栏、首字下沉、避头尾、孤行寡行控制……哪些是第一版必需？
4. 用户怎么控制版式：选几套预设模板，在设置里调参数，还是像 Typst / LaTeX 那样写模板（也可以交给助手写，像空间主页一样）？
5. 排版引擎：直接用 Chromium 的打印排版（CSS 分页媒体 + `printToPDF`，成本最低），引入 Paged.js 这类分页库，还是内置 Typst（质量与速度更好，但要把 Markdown 转成 Typst，且是新的依赖）？这一项难以撤销，定下来时写 ADR。
6. 预览方式：在卡片里切到“页面视图”看分页结果，还是单独的导出窗口？
7. 文件：排版设置跟着笔记（写在 frontmatter 或 `.notes/` 里），还是跟着应用（settings.json）？导出物放在哪里？

## 初步思路（未经确认）

- 最小可用：Markdown → 现有排版的 HTML → 打印样式表（`@page` 纸张、页边距、页码）→ Electron `webContents.printToPDF` 导出，再加几套模板。
- 想要“强大”（论文、书籍级别的分页、脚注、引用、目录）：考虑内置 Typst，由 Markdown 转换，模板可由助手编写。
