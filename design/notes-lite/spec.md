# 独立 macOS 笔记软件：三栏资料库、整页专注编辑与 Metal 流动动效

日期：2026-10-16。状态：产品方向和完整验收范围已由用户确认；规格已进入本地 Markdown 跟踪；NotesLite 已实现首个可运行版本，完整验收仍在进行，见 `../../NotesLite/evidence/verification.md`。

## Problem Statement

用户希望获得一个只围绕笔记工作的独立软件。原产品包含 Agent 面板、会话、伴写、提案审阅、研究台、流水线、自动化及外部控制接口，功能与后台行为超出了这次产品的需求。仅隐藏 Agent 按钮不能满足要求。

用户同时希望保留原产品的当前版本，而不是把它改造成简化版；新软件应保留本地 Markdown 的直接性，并拥有轻盈、有弹性、柔软流动的界面。日常整理需要清晰的资料库，进入写作时则需要整个编辑空间只呈现笔记。

## Solution

构建独立的 macOS 笔记软件，保留原产品及其现有功能与版本。默认采用已选定的 B「清晰资料库」布局：文件夹、笔记列表、正文三栏；提供整页专注模式，收起导航、列表、工具栏、元信息和状态栏，仅呈现笔记标题与正文，并能便捷返回。

保留本地 Markdown 创建、编辑、自动保存、文件夹、搜索、最近打开、笔记链接、图片与附件，以及代码块、表格和公式显示。编辑以直接书写 Markdown、原地显示排版为核心，保留查看和编辑源码的能力。

采用用户已确认的 SwiftUI 界面、AppKit 文本编辑器和 Metal 特效组合。动效采用已选定的「柔软流动」方向：弹性响应、轻微惯性与回弹，浮层折射、边缘高光、短暂交互波纹，以及面板展开和收拢时的轻微形变。文字保持清晰稳定；专注模式的静止状态保持安静。

## User Stories

2. 作为原产品用户，我希望新软件不覆盖原应用及其偏好设置，以便两者可以分别运行和演进。
3. 作为笔记用户，我希望直接打开本地笔记库，以便继续管理自己的 Markdown 文件。
4. 作为笔记用户，我希望新建笔记并立即输入，以便快速记录想法。
5. 作为笔记用户，我希望编辑笔记标题，以便识别和查找文档。
6. 作为笔记用户，我希望正文自动保存，以便不必反复执行保存操作。
7. 作为笔记用户，我希望切换笔记、关闭窗口和退出应用后能重新打开已保存内容，以便确认记录没有丢失。
8. 作为中文写作者，我希望中文输入、选区、光标和撤销重做正常工作，以便连续写作。
9. 作为 Markdown 用户，我希望直接书写 Markdown 并原地看到排版，以便减少编辑和预览之间的切换。
10. 作为 Markdown 用户，我希望能够查看和编辑源码，以便精确控制文档内容。
11. 作为笔记用户，我希望标题、段落、强调、引用和列表得到正确显示，以便组织可读的内容。
12. 作为笔记用户，我希望代码块得到正确显示，以便记录技术内容。
13. 作为笔记用户，我希望表格得到正确显示，以便整理结构化内容。
14. 作为笔记用户，我希望行内与独立公式得到正确显示，以便记录数学内容。
15. 作为笔记用户，我希望管理文件夹并整理笔记，以便维持清晰的笔记库。
16. 作为笔记用户，我希望重命名、移动和删除笔记时结果清楚且可控，以便整理内容而不误失资料。
17. 作为笔记用户，我希望按标题和正文搜索，以便找到需要的信息。
18. 作为笔记用户，我希望查看最近打开的笔记，以便快速返回正在处理的内容。
19. 作为笔记用户，我希望创建并打开笔记之间的链接，以便连接相关内容。
20. 作为笔记用户，我希望加入并查看图片，以便保存图文笔记。
21. 作为笔记用户，我希望添加和打开附件，以便将相关资料保存在笔记库中。
22. 作为笔记用户，我希望在默认界面同时看到文件夹、笔记列表和正文，以便连续浏览与整理。
23. 作为笔记用户，我希望列表选中项与正在编辑的笔记始终对应，以便明确当前操作对象。
24. 作为写作者，我希望一键进入只呈现标题和正文的专注模式，以便减少界面干扰。
25. 作为写作者，我希望通过退出入口或 Esc 返回三栏界面，以便随时继续查找资料。
26. 作为写作者，我希望进入和退出专注模式时保留当前内容、光标、选区和阅读位置，以便不打断思路。
27. 作为写作者，我希望专注模式下仍能正常编辑和保存，以便专注状态具备完整写作能力。
28. 作为界面使用者，我希望面板与浮层运动轻盈、有弹性，以便操作感觉自然连贯。
29. 作为界面使用者，我希望能够在动画中途继续操作或反向切换，以便不必等待转场结束。
30. 作为界面使用者，我希望看到真实的 Metal 折射、光影与短暂波纹，以便获得已选定的柔软流动视觉体验。
31. 作为写作者，我希望特效不扭曲正文、不遮挡内容、不影响命中区域，以便保持阅读和输入的准确性。
32. 作为写作者，我希望停止操作后画面安静下来，以便长时间写作时不会受到持续动态干扰。
33. 作为笔记用户，我希望输入、滚动、搜索和笔记切换保持响应，以便漂亮动效不以卡顿为代价。
34. 作为纯笔记软件用户，我希望启动和使用时不启动 Agent、模型调用、自动化或外部控制服务，以便应用行为与笔记定位一致。
35. 作为纯笔记软件用户，我希望界面、菜单、快捷键、设置和引导都围绕笔记，以便不再看到失效的 Agent 入口。
36. 作为原产品用户，我希望打开已有 Markdown 资料时不删除旧协作资料，以便原产品仍能继续使用自己的数据。
37. 作为交付验收者，我希望在真实 macOS 应用中检查笔记功能、专注模式、Metal 效果和流畅度，以便网页原型和构建成功不会被当作完整交付。

## Implementation Decisions

### 已确认的产品与架构决定

- **独立产品边界**：新软件与原产品分别演进。原产品的 Agent 模式平台定位及既有架构决定仍适用于原产品，不自动继承为新软件的需求。保留原产品已有未提交修改，不通过覆盖旧工程完成简化。
- **平台与实现组合**：首版为 macOS 原生应用，SwiftUI 构建应用界面，AppKit 承载文本编辑，Metal 实现复杂视觉效果。不以网页原型的实现技术决定正式应用技术栈。
- **功能边界**：本地笔记能力属于核心；全部 Agent 联动属于排除范围。排除不仅涉及界面，还包括启动路径、后台任务、进程、定时扫描、模型配置和控制接口。
- **界面配色**：用户在实现阶段明确排除临时绿色配色；新应用使用中性的灰白色，并跟随系统切换深色外观。
- **默认布局**：B「清晰资料库」，文件夹、笔记列表、正文三栏。A、C 为设计比较方案，不作为额外交付模式。
- **专注模式**：隐藏文件夹、笔记列表、应用工具栏、元信息和状态栏；保留当前笔记标题与正文、低显著度退出入口，以及 Esc 返回能力。专注模式是编辑布局状态，不另建笔记或编辑副本。
- **编辑语义**：本地 Markdown 是正文来源；直接书写、原地排版与源码控制围绕同一文档工作，不维护彼此可能失步的两份正文。
- **动效风格**：选择「柔软流动」，采用轻盈弹性、轻微惯性与回弹；Metal 承载浮层折射、边缘高光、短暂交互波纹和面板轻微形变。具体参数通过原生样例校准，不把任意参数宣称为用户已确认值。

### 交付所需的工程约束

以下是依据已确认目标形成的实现约束，不代表用户另外指定了具体库、存储格式或性能数值。

- **模块边界**：将应用外壳、笔记库与文档操作、Markdown 编辑与渲染、导航搜索、视觉动效分别组织；文本内容与保存状态不依赖动画生命周期。
- **复用原则**：优先检查原产品纯笔记能力是否可独立复用。不能为了复用编辑器而将 Agent 运行、协议、会话或后台服务器带入新应用；允许提取或复制必要能力，不要求重写所有解析逻辑。
- **应用隔离**：使用独立应用身份、偏好设置及应用支持空间，避免覆盖原产品。正式命名与最低系统版本在工程落地时明确，当前不新增未经确认的品牌或系统版本承诺。
- **笔记库契约**：正文与附件保持本地可访问。新应用不因打开已有目录而生成 Agent 规则、接管旧协作记录或清除原产品元数据。旧协作资料的转换不在本规格内。
- **保存与错误反馈**：自动保存应真实反映磁盘结果；写入失败不能显示保存成功。切换和退出需要处理未保存状态；外部文件修改不能静默覆盖用户未保存内容。具体冲突呈现由实现确定并在验收中展示。
- **笔记与附件操作**：重命名、移动及附件导入要维护可解析的引用。名称冲突、丢失链接、不可读附件和无搜索结果应有可理解反馈；删除应使用可恢复方式。
- **编辑连续性**：中文组合输入、选区、撤销重做、光标与滚动位置不得因重排、切换源码视图或专注转场被不必要地重置。无需为动画重建文档。
- **布局响应**：宽窗口呈现三栏；窄窗口仍须保证正文可编辑和导航可达。具体最小宽度、栏宽调整与恢复策略由原生样例验证，不沿用原产品的三栏尺寸作为冻结要求。
- **动效分工**：SwiftUI 负责可中断的弹簧响应、界面层级和布局转场；Metal 负责受限区域的材质和短时效果。输入、保存、搜索和文档切换不等待特效完成。
- **视觉稳定性**：正文文字不应用影响可读性的折射或波纹。特效结束后停止相关持续刷新；专注模式静止状态不播放循环波纹、漂移或呼吸动画。
- **特效不可用时的退化**：提供 Metal 不可用时的可用界面；功能、文字对比度和命中区域不以复杂特效存在为前提。
- **原型定位**：现有 HTML 原型是三种结构及专注状态的比较证据，不能作为实时 Markdown 渲染或 Metal 实现的证明。采用 B 的决定与专注语义保留，原型代码不直接提升为生产实现。
- **原型归档**：将原型作为一次性设计来源保存至独立临时分支，并在问题跟踪工具中记录选定 B 的结论和来源指针；归档不得夹带原产品已有修改。归档已完成：`codex/notes-lite-prototype`，提交 `631f9c9`。

## Testing Decisions

用户已选择完整验收范围：核心笔记功能、原软件不受影响、无 Agent 后台联动、真实 Metal 效果、动画流畅度与专注模式体验。

### 主要测试边界

- 以**真实应用操作临时笔记库后的可见状态与磁盘结果**为主要端到端边界。测试覆盖用户流程，不与具体视图层级、私有属性、动画实现或内部函数调用绑定。
- 尽量复用同一组笔记库样例和少量应用级操作。仅为界面难以稳定覆盖的解析边缘情况保留聚焦的纯逻辑测试，不给每一层建立重复的模拟边界。
- 测试样例包括中文、空笔记、同名候选、子文件夹、相对路径图片与附件、笔记链接、代码块、表格、行内和独立公式，以及较长的 Markdown 文档。

### 核心验收矩阵

| 范围 | 用户操作与场景 | 验收证据 |
| --- | --- | --- |
| 独立应用 | 安装、启动新应用；再启动原产品 | 两个应用身份与偏好互不覆盖；原产品仍可使用；已有源代码修改未被覆盖 |
| 笔记持久化 | 新建、中文输入、自动保存、切换、关闭、重新打开 | 实际磁盘正文与用户输入一致；失败时有反馈，不出现虚假保存状态 |
| 文件组织 | 创建文件夹、重命名、移动、恢复删除；触发名称冲突 | 文件位置与界面一致，引用保持正确，冲突不造成覆盖 |
| 搜索与导航 | 按标题和正文搜索、选择结果、访问最近打开 | 选中项、编辑对象与实际文件一致；无结果时有清晰状态 |
| 编辑与排版 | 编辑标题、列表、代码、表格、公式；切换源码控制 | 排版正确，Markdown 保真；中文组合输入、撤销、选区和光标可用 |
| 链接与附件 | 链接跳转、添加图片与附件、移动相关笔记 | 引用可解析，图片可见，附件可打开；失效目标有反馈 |
| 专注模式 | 从 B 进入、编辑、保存，通过退出入口及 Esc 返回；快速反向切换 | 专注时仅标题与正文为主体；返回恢复原选择和编辑位置；内容不丢失，操作不被转场锁定 |
| Metal 视觉 | 在原生应用中触发浮层、波纹和面板转场 | 实际 Metal 渲染路径运行，提供运行证据与录屏；不能用 Web、静态截图或纯 SwiftUI 效果代替 |
| 视觉质量 | 检查折射、高光、波纹、形变与连续重定向 | 呈现选定的柔软流动风格；正文可读、输入准确；无闪跳、残影或不合理大幅回弹 |
| 运行流畅度 | 输入、滚动长文、搜索、切换笔记、展开面板和反复专注切换 | 记录实际机器、系统、文档规模和采样方式；检查卡顿、主线程阻塞与帧时间，不以编译通过代替性能验证 |
| 静止与特效退化 | 停止交互、验证特效不可用的退化行为 | 静止后无无意义持续渲染；正文可读且应用可操作 |
| 无 Agent 联动 | 从冷启动到编辑、搜索、附件和退出的完整流程 | 检查进程、监听端口、子进程及应用生成的数据；无 Agent/模型调用、服务器、自动化或规则注入；同时审计菜单、设置与命令入口 |
| 原有数据兼容 | 使用临时复制的旧笔记库，记录前后文件变化 | 仅预期的笔记操作改变文件；旧协作元数据保持不动，原产品仍可读取其资料 |

### 测试先例与限制

- 原产品已有 XCTest 对 Markdown 块级/行内语法、表格、公式、代码高亮、链接改名和索引行为进行纯逻辑检查。独立复用的笔记核心可继承相应测试用例，不继承 Agent 协议测试作为新产品功能。
- 原产品已有基于临时笔记库的端到端脚本，其隔离样例与检查磁盘结果的思路可借鉴；脚本依赖旧 CLI、socket、HTTP 与 Agent 操作，不能直接搬入新产品，更不能为测试便利重新引入已排除的控制服务。
- SwiftUI/AppKit/Metal 的显示效果、输入连续性和实际流畅度必须在原生应用中检查。构建成功、逻辑测试通过、网页原型演示均不足以单独完成验收。
- 当前没有新软件运行数据，也没有用户确认的帧率、内存、延迟或笔记库规模数值；实施时记录测试条件和测量结果，任何新增硬性数值门槛应明确标记，不能引用旧计划的历史指标作为本次实测。
- 对于本机无法覆盖的硬件或退化情形，交付时明确注明未验证项；不得将代码分支存在描述为实际运行通过。

## Out of Scope

- 专门适配系统“减少动态效果”设置、为其设计替代动画，以及相关专项验收（用户明确排除）。

- 替换、删减、重命名或重构原产品；覆盖其已有未提交修改。
- Agent 面板、CLI 启动与检测、会话、模型配置、伴写、AI 批注、提案审阅、研究台、问库、流水线、自动化、生成式工作区、Agent 插件与规则生成。
- 为外部 Agent 提供 MCP、socket、HTTP、命令注册表或其他控制入口。
- 将 A、B、C 做成三个正式布局产品，或交付原型中的方案选择条。
- 实时 MD/HTML 双向同步、可编辑 HTML 产品线、自定义模式平台、图谱、知识研究平台与复杂嵌入系统。
- 多人协作、账号、云服务、专用同步协议、移动端、Windows 与 Linux 首版。
- 把旧协作记录转换为新软件数据，或主动清理旧产品元数据。
- 正文文字持续变形、循环装饰动画、打字粒子，以及等待动画后才能继续操作的流程。
- 以静态图、网页动画或复杂特效开关替代真实 Metal 效果交付。

## Further Notes

- 本规格的产品依据为本轮已确认对话及独立笔记领域术语表；原产品的三份 Agent 模式架构决定保留在原有上下文，不被本规格废止。
- 设计结论：保留原产品；新建独立笔记软件；B 三栏；整页专注模式；Markdown 原地排版与源码控制；柔软流动动效；macOS 原生 SwiftUI、AppKit 与 Metal 组合。
